## Why it still fails, named

Four defects were found by giving the world a door. All are REPORTED, not
patched: the card that added the world explicitly forbids touching navigation
source. Each has a pinned witness in `tests/test_portal_world.py` that goes red
when the defect is fixed, so this addendum cannot go stale silently.

* **R14-D1 — the hosted lane files the door as furniture.**
  `arrival_semantics.classify_place` tests the caller-supplied scene vocabulary
  as a whole phrase *before* it tests its own portal word list against the head
  noun, and `semantic_goal_from_directive` strips the article. So the owner's
  "go to the door" arrives as `door`, matches the sidecar's new class name, and
  is classified `object`: `do_not_cross` False, ask-hint empty. The typed panel
  and the brain router pass no vocabulary and still get `portal`. The extension
  mechanism is implemented as an override, and it was *this world change* that
  armed it.
* **R14-D2 — the do-not-cross guard has no polygon to test.**
  `pipeline._apply_arrival_etiquette` refuses a threshold pose only when
  `result.polygon` is non-empty; the shipping perception seam emits `polygon`
  for region tracks only, and a portal is necessarily object-kind. The guard is
  unreachable on the product path. R10's pipeline test passes because it hands
  the guard a polygon invented in the test file.
* **R14-D3 — `near` is two geometries wearing one name.** The planner's goal
  region is a centre-distance band sized with the anchor's *circumscribed*
  radius; the verifier re-expresses it as a LiDAR surface band by subtracting
  that same radius, which is exact only for a disc. For the door leaf
  (aspect 6.67) the planner commits a pose inside its own band that the verifier
  is guaranteed to reject — which is precisely `semantic_arrival_verification_failed`
  above. **Pre-existing, not introduced here**: `bench_1` (aspect 3.18) fails the
  same arithmetic and "go to the bench" ends `semantic_target_unreachable`
  today. Enumerated over the approach half-plane, 4953 poses on the sidewalk
  satisfy *both* predicates, so this is a selection defect, not impossible
  geometry.
* **R14-D4 — the rig's obstacle set is a second, unsynchronised scene
  vocabulary.** `headless_city._STATIC_OBSTACLE_PREFIXES` does not contain
  `door_`, so the block's only portal casts no LiDAR return in the quality rig.
  Measured: splicing it in changes nothing here, because D3 rejects the terminal
  either way.
