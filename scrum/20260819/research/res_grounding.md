# Literature sweep: LLM-grounded robot task execution & hierarchical control (for Parcel)

## Key works

### 1. SayCan — "Do As I Can, Not As I Say" (Google, 2022)
**What it does.** The first prominent system to split "what is useful" from "what is possible": a frozen LLM scores which skill would advance the instruction, while learned value functions (affordances) score which skill can actually succeed from the current state; the product picks the action. Grounding via affordances roughly doubled plan success over ungrounded LLM planning across 101 real kitchen tasks. Critically, common sense about *feasibility* lives outside the LLM, in grounded value estimates.
**Why it matters for Parcel.** Scenario 3 ("circle around me" while owner sits at a desk) is a textbook affordance veto: the instruction is linguistically fine but physically/socially inadmissible right now. SayCan's architecture says that veto must be computed by the local grounded layer (plan admission + keepout geometry), never by asking the hosted mini model to notice. But SayCan's known weakness is that it vetoes *silently* by rescoring — Parcel's owner explicitly requires the robot to SAY it cannot orbit. SayCan also famously cannot recover from failures because no feedback returns to the LLM (which motivated Inner Monologue).
**Design implications.** Plan admission should return typed, owner-facing refusal reasons (e.g. `orbit_infeasible:person_at_furniture`), and a refusal must be in the always-forward band with an obligation on the voice layer to verbalize it. The affordance check itself (orbit clearance annulus around the owner's seated pose vs. desk keepout) is deterministic local geometry, not judgment.

### 2. Inner Monologue (Google, 2022) — the closest prior art to the whisperer
**What it does.** Continually injects short natural-language feedback lines into the LLM planner's prompt as the robot acts, in three types: **success detection** (binary, per action), **passive scene description** (structured object/state text provided automatically), and **active scene description** (answers to questions the LLM itself asks, including questions to the human). Closed-loop language feedback substantially improved long-horizon completion in sim and real kitchens, with no fine-tuning. Feedback is per-action/event-based, not per-tick, is short, and is robust to reordering and typos. It applies **no significance filtering** — everything is forwarded — which is viable only because tabletop action granularity is seconds-to-minutes.
**Why it matters for Parcel.** This is the whisperer's direct ancestor and validates its core bet: state fed back *as terse natural language, at event granularity* measurably improves LLM task behavior. Parcel's three bands map cleanly onto Inner Monologue's taxonomy: success/terminal detection → always-forward; passive scene description → the judge band (IM forwarded it all; at Parcel's 10–20 Hz that's impossible, hence the filter IM never needed); active description → the ask-the-owner path in scenarios 2 and 4. IM also establishes that the LLM asking questions is itself a feedback channel, not an afterthought.
**Design implications.** Keep injected items in IM's shape: one short sentence, event-anchored, typed prefix ("Success:", "Scene:", "Blocked:"). Parcel's coalesced "+N more proximity changes" lines in `proof_final.txt` are exactly the right compression. IM's unfiltered firehose is the failure mode Parcel already hit live (69 narrations from one turn, R4L session 1) — the three-band policy is the missing piece IM's setting let it skip.

### 3. Code as Policies (Google, 2022)
**What it does.** Prompts an LLM to write executable Python "language model programs" that call perception APIs and control primitives, with loops/conditionals, turning instructions into reactive policies. Common sense lands in generated code: spatial-relational grounding ("to the left of", "faster") becomes parameterized geometry. Generalizes to unseen instructions; known risks are hallucinated APIs and un-vetted control flow.
**Why it matters for Parcel.** Parcel deliberately refuses to let the LLM synthesize policy — right call for a motion platform. But CaP's lasting insight applies anyway: scenario 1 ("end ON TOP of the sidewalk") is a *predicate-composition problem, not a language problem*. "Arrived" must be a named geometric predicate — `contains(sidewalk_polygon, robot_footprint)` — not a distance-to-centroid threshold. The `semantic_target_unreachable` failure in the live proof and `goal=3.4m` reason strings suggest arrival is currently range-based.
**Design implications.** Give every `navigate_to` target a typed termination predicate (ON for surfaces, NEAR+FACING(owner) for scenario 2's door). Keep the predicate library local and hand-written; let the intent router select predicates, never author them.

### 4. PaLM-E and RT-2 (Google, 2023) — the end-to-end counterpoint
**What they do.** PaLM-E (562B) interleaves continuous sensor embeddings into a language model that emits high-level text plans consumed by low-level policies; RT-2 co-fine-tunes a VLM to emit action tokens directly (a true VLA), with chain-of-thought before action tokens. Together they mark the field's fork: end-to-end VLAs achieve semantic generalization but demand enormous data, embodiment-specific training, and on-board inference at control rate — none available to a hosted voice model.
**Why it matters for Parcel.** They define why Parcel's architecture is the right one for this stack: a hosted, generalist, non-embodied model can never be in the motion loop, so the hierarchy (hosted proposes discrete tools, local disposes) is not a compromise but the only sound topology. PaLM-E also shows state was fed as fresh tokens per query — there was no persistent session accruing stale items, which is precisely the new problem Parcel's realtime session introduces (see Statler).
**Design implications.** None to copy; the lesson is confirmation plus a boundary: don't creep toward letting the hosted model emit anything finer-grained than the current five tools.

### 5. Statler (TTIC/UChicago, 2023) — explicit world state as memory
**What it does.** Maintains an explicit structured world-state text that two prompted LLM roles read and write (world-model reader / world-model writer), because context-window scrollback is a terrible state store: stale facts and long-horizon drift corrupt reasoning. Significantly outperforms scrollback-reliant baselines on long-horizon manipulation.
**Why it matters for Parcel.** The hosted realtime session is append-only: every injected system item stays in context forever, and the mini model — already shown weakly compliant (R5's two-beat and over-claim defects) — will happily answer from a superseded item. The whisperer's dedup prevents *sending* duplicates but cannot *retract* what was already sent. Statler says: keep the canonical state outside the model (Parcel already does — `get_status`), and make every injected item self-invalidating.
**Design implications.** Stamp injected items with a monotonic state version and phrase them as deltas ("as of t=96s, mission to sidewalk: searching again, prior block released") so newer items lexically supersede older ones. Treat `get_status` as the authoritative read path and say so in the SI. Related: BLINDER ("Selective Perception," 2023) learns minimal task-conditioned state descriptions for LLM actors with RL — evidence that *which fields* to include is itself an optimizable policy; Parcel's fixture corpus + Qwen AutoRater could tune the judge's field selection offline the same way.

### 6. KnowNo — "Robots That Ask For Help" (Princeton/DeepMind, 2023)
**What it does.** Uses conformal prediction to calibrate when an LLM planner is uncertain enough that it should stop and ask the human, with statistical guarantees on task success at minimal help frequency. Frames asking as a precision instrument: over-asking destroys autonomy and trust, under-asking destroys correctness. Generates candidate next actions and asks the human to disambiguate among them.
**Why it matters for Parcel.** Scenarios 2 and 4 are ask-for-help behaviors ("turn back and ask what to do next"; "ask whether to just walk"), and scenario 3 is a calibrated refusal. KnowNo's core warning applies with force: relying on the mini model's *own initiative* to notice ambiguity is uncalibrated vibes — and R4L/R5 already document weak instruction compliance. The trigger for asking must be structural.
**Design implications.** Build typed local detectors that raise ask-events: pace-mismatch (owner gait speed vs. commanded follow pace), goal-reached-now-what (door postcondition), infeasible-orbit. These events go in the always-forward band with the *question already drafted* by the local chain; the hosted model's job shrinks to voicing it. KnowNo's multiple-choice trick is directly reusable: inject "options: keep running pace / slow to walk" so even a weak model answers well.

### 7. Boston Dynamics Spot tour guide (2023) → Spot + Gemini Robotics-ER (2025–26) — the production quadruped analog
**What it does.** BD wired ChatGPT to Spot with a ~1 Hz structured state dictionary (current location ID + description, nearby reachable locations, BLIP-2 camera captions, speech transcripts) and exactly three whitelisted verbs: `go_to(location_id, phrase)`, `say(phrase)`, `ask(question)` — locomotion stayed entirely inside the proven autonomy SDK, and `go_to` was constrained to pre-mapped nearby nodes to bound hallucination. Failures: 6+ s response latency, confident fabrications ("Stretch is for yoga"), total dependence on internet uptime; surprise: rich emergent behavior from statistical association. In 2025–26 Spot moved to Gemini Robotics-ER as the reasoning layer, with Google's own guidance that model-level safeguards are *not* a substitute for local safety engineering (e-stops, collision avoidance stay local).
**Why it matters for Parcel.** This is the closest deployed relative: hosted generalist brain, deterministic quadruped body, voice interaction. It validates Parcel's tool surface almost verb-for-verb and shows a 1 Hz *tiny structured snapshot* was enough for coherent tours — their feed needed no significance judge only because the state was a five-field dict. It also previews Parcel's outage reality: the live proof shows `stalls: 2` in a two-minute session, and the deterministic yield-policy utterances carried the entire pedestrian-block conversation while the model was quiet. That fallback channel is load-bearing; BD had none and simply went mute offline.
**Design implications.** Keep the deterministic utterance channel forever (model-off non-inferiority gate is exactly right). Constrain `navigate_to` arguments to a known-entity vocabulary the way `go_to` was location-whitelisted. Expect and eval fabrication when scene items are injected.

### 8. YAY Robot — "Yell At Your Robot" (Stanford/Berkeley, 2024)
**What it does.** Hierarchical policy where a high-level model emits language commands to a language-conditioned low-level policy; a human's spoken correction *overrides the high-level output in real time*, and corrections are logged to fine-tune the high level. The language command channel doubles as the intervention interface.
**Why it matters for Parcel.** Mid-mission owner speech ("actually, stop", "not that door") must preempt the current mission at the intent-router level, not queue behind the hosted turn loop — especially given observed multi-second stalls. And scenario 4's clarifying question must remain interruptible by the answer.
**Design implications.** Owner speech is always-forward *inward* (never judge-gated) and should carry preemption semantics in the task executive. Log every owner correction with the state that preceded it — that's free fine-tuning/eval data for Gemma and the fixture corpus.

### 9. Talker-Reasoner (Google DeepMind, 2024)
**What it does.** Dual-agent architecture explicitly modeled on Kahneman: a fast Talker converses continuously while a slow Reasoner updates beliefs, plans, and calls tools, communicating through a shared belief state in memory. Names the key failure mode: the Talker can fluently assert things the Reasoner has not yet established, and identifies the states where the Talker *must wait* for the Reasoner.
**Why it matters for Parcel.** Parcel's voice model is a Talker; the local chain plus Gemma is the Reasoner side. The R5-documented defects — the model re-announcing a navigation it already announced (two-beat tool turn) and claiming inability while its gesture executed (over-claim) — are precisely Talker-asserts-unconfirmed-belief failures. The literature says this class of bug is architectural, not promptable-away on a weak model.
**Design implications.** Define the must-hedge states explicitly (mission accepted but not started; tool result pending) and put the *facts* in the deterministic channel, letting the model only paraphrase. The shared belief state should be the injected versioned deltas from item 5, not the model's own scrollback.

### 10. Figure Helix (2025) and NVIDIA GR00T N1 (2025) — the System 1/System 2 VLAs
**What they do.** Helix: a 7B VLM "System 2" at 7–9 Hz distills scene + language into a single continuous latent vector that conditions an 80M "System 1" visuomotor policy at 200 Hz; both see the same sensors, S1 keeps reacting while S2 thinks; the stated motivation is letting each layer run at its natural timescale and iterate independently. GR00T N1 is the same shape (VLM System 2 → diffusion-transformer System 1), trained jointly end-to-end. Helix 02 (2026) extends this to full-body autonomy.
**Why it matters for Parcel.** The industry's flagship architectures independently converged on Parcel's split — that's strong validation of hosted-slow/local-fast. But note two disanalogies: (a) their S2 is *local* and 7–9 Hz; Parcel's is remote, ~1000× slower, and demonstrably stall-prone, so Parcel's local chain must be *complete* without S2, not merely faster; (b) their interface is a trained latent, so compatibility is learned by gradient — Parcel's interface is untrained discrete tools + text, so compatibility must be enforced by schema validation and plan admission. GR00T's joint training is the reason their S1 never misreads S2; Parcel has no such guarantee, only the broker.
**Design implications.** Treat the tool schema + admission rules as the "training" of the interface: reject early, reject loudly, and always-forward every rejection so the model can repair. The existing `refused_tool_calls`/`rejected` counters are the right observability.

### 11. Hi Robot (Physical Intelligence, 2025) — cadence and interjections, published
**What it does.** A high-level VLM re-plans **every 1 second OR immediately upon user interjection**, emitting a plain-language atomic command ("pick up the lettuce") to a low-level VLA (π0); it can also speak via TTS before acting. Trained on synthetic "situated feedback" (corrections like "that's not trash", constraints, negations) generated by prompting a bigger VLM over demo segments. Beat a GPT-4o-as-high-level baseline by **40+ points of instruction accuracy** — the API generalist was the weakest configuration. Self-identified limitations: fixed 1 s cadence rather than adaptive, and the two layers being mutually unaware of each other's capabilities.
**Why it matters for Parcel.** Three direct hits. First, its cadence — periodic ~1 Hz *plus* event-triggered on user input — is published precedent for the whisperer's periodic+event design, and its "should be adaptive" limitation is exactly the gap Parcel's judge band proposes to fill. Second, the GPT-4o result is a quantified warning that a hosted generalist underperforms a situated fine-tuned model at contextual instruction following — consistent with the observed weak compliance of `gpt-realtime-2.1-mini`, and an argument for shifting scenario 2–4 interpretation into the local chain/Gemma with the hosted model as mouth. Third, its synthetic-feedback recipe (generate corrections/constraints over logged episodes with a big model) is directly reusable: Parcel's 25 fixture threads + mission logs → synthetic scenario 2–4 training/eval cases via the Qwen judge.
**Design implications.** Adopt "1 Hz OR event" as the whisperer's outer loop; make owner interjection a hard trigger. Budget an eval that measures instruction accuracy of the mini model specifically on injected-state turns, since this is where generalists fail.

### 12. OneTwoVLA (2025) — a learned significance policy
**What it does.** A single unified model that adaptively switches between acting and explicit reasoning, choosing to reason only at **critical moments**: subtask completion, error/anomaly detection, and when human input is needed; otherwise it acts on its most recent reasoning. Motivated explicitly by dual-system latency and the mutual-blindness of decoupled layers.
**Why it matters for Parcel.** This is the literature's answer to "when should the slow layer be engaged," and its learned critical-moment taxonomy — subtask boundaries, errors, need-human-input — is nearly identical to Parcel's proposed always-forward band. Notably, it triggers on *typed events*, not on a scalar significance score.
**Design implications.** Strong pressure to make the judge band's output a typed classification (progress-milestone / scene-change / social-event / none) rather than a raw importance score — typed events are testable against the fixture corpus and align with the block-class machinery (`person_stop`/`obstacle_stop`) that already exists in the nav reason strings.

## Design pressure: what the literature says about the drafted three-band whisperer

**What the draft gets right.**
- **The topology is the consensus.** Hosted/slow proposes, local/fast disposes, with safety local: SayCan → Spot → Helix/GR00T → Gemini-ER's own developer guidance all converge here. Google explicitly tells developers that model-level safeguards don't substitute for local safety engineering — Parcel's SafetySupervisor-owns-motion rule is the published best practice.
- **Language-formatted, event-anchored feedback works.** Inner Monologue proved terse natural-language feedback lines measurably improve LLM task behavior; Hi Robot's 1 Hz + interjection cadence and OneTwoVLA's critical-moment gating are precedent for both the periodic drip and the event triggers. Nobody in the literature forwards per-tick telemetry to the language layer; never-forward for tick data is unambiguously correct.
- **Hard caps and dedup outside the judge.** BD Spot's whitelisting philosophy (determinism bounds the model, not vice versa) and Parcel's own live incident (69 narrations from one turn) both say the rate limiter must be a dumb outer wall, not a judge behavior. R4L's floor gate + coalescing already embodies this.
- **The deterministic utterance channel is load-bearing, keep it.** In the live proof the entire pedestrian-block conversation was carried by hardcoded yield-policy lines while the hosted model stalled twice. Talker-Reasoner and the Spot outage story both endorse a model-free audible path; the model-off non-inferiority gate is ahead of the literature here.

**What it gets wrong or is missing.**
1. **Scalar significance is the weakest part of the design.** KnowNo's entire thesis is that uncalibrated LLM confidence/importance judgments are unreliable, and OneTwoVLA/Hi Robot trigger on *typed events*, not scores. Recast the judge band: Gemma classifies accumulated deltas into a small typed taxonomy (progress-milestone, scene-change, social-event, nothing) with per-type forwarding rules, and calibrate any threshold offline against the 25-thread fixtures with the Qwen AutoRater. A scalar 0–10 "importance" from Gemma will drift and is untestable.
2. **No retraction story for an append-only session.** The realtime session accumulates every injected item forever; dedup at the sender can't stop the model answering from a stale item (Statler's core problem, and the mini model already exhibits belief-ordering bugs — two-beat turn, over-claim). Version-stamp every injected delta, phrase items as supersessions ("update: ..., replaces earlier block report"), and declare `get_status` the sole authoritative read in the SI.
3. **Common sense is currently homeless.** The four scenarios are implicitly assigned to the hosted mini model's judgment, but Hi Robot quantified that an API generalist is the *worst* place for situated instruction interpretation (−40 points vs. fine-tuned local), and R4L/R5 observed the same weakness live. The literature's placement: scenario 1 is a **termination predicate** (Code as Policies — ON-surface containment, local geometry); scenario 2 is a **postcondition + drafted question** (near + reorient-to-owner + ask, raised as a typed event); scenario 3 is an **affordance veto with a mandatory owner-facing reason string** (SayCan + the owner's say-it requirement); scenario 4 is a **local mismatch detector** (owner gait vs. commanded pace) raising an always-forward ask-event with KnowNo-style pre-drafted options. In all four, the hosted model phrases; the local chain decides.
4. **Asking is not yet a first-class channel.** Inner Monologue, KnowNo, and Spot all give the language layer an explicit `ask(question)` verb; Parcel's tool list has none, so clarification currently depends on the weak model's initiative. Either add an ask/confirm affordance or (better, given compliance data) have local detectors inject the drafted question through the narration channel with an instruction to voice it.
5. **Progress is the missing feedback type.** The bands cover safety, terminals, and refusals, but Inner Monologue's highest-value signal was per-action success/progress, and Gemini-ER productizes progress estimation. Mid-mission milestones (route replanned, distance bands crossed, "released that approach, trying another way" — already generated in the nav reasons) belong in the judge band's output so the voice model can answer "how's it going" without a tool round-trip and can narrate the *story* of a two-minute blocked mission rather than its endpoints.
6. **Un-considered pitfall — fabrication under injection.** Spot fabricated confidently from thin context ("Stretch is for yoga"). Once scene/state items flow in, the mini model will embellish (claim distances, invent obstacles). Add an AutoRater eval scoring narration turns for facts not present in any injected item or tool result.
7. **Un-considered pitfall — self-conditioning on repeated items.** The transcript in `proof_final.txt` shows near-identical deterministic lines recurring; in an append-only session these act as few-shot examples teaching the model to parrot the pattern (and to re-announce — plausibly a contributor to the two-beat defect). Vary the deterministic phrasings or mark them as system-origin so the model doesn't imitate them.
8. **Un-considered pitfall — judge availability.** The whisperer adds a second remote-ish dependency (Gemma at :8080). Hi Robot's decoupling caveat applies: define fail-open/fail-closed per band now — judge down should degrade to "forward nothing but always-forward band," never to "forward everything."
