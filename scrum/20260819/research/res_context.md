# Literature Sweep: Streaming Context Injection & Proactive Dialogue for Parcel

Angle: how to feed robot state into a hosted realtime voice model without making it noisy, and when a companion agent should speak unprompted.

---

## Key works

### 1. OpenAI Realtime API official guidance on mid-session context (OpenAI, 2024–2026)
**What it does:** The official realtime conversation docs state that `conversation.item.create` can add items "mid-stream," and that system messages "can be added at any point in the conversation" — with the explicit rule of thumb: use `session.update`/instructions for *major* behavior changes, and injected **system messages** for *smaller* contextual updates ("the user is now asking about a different topic"). `response.create` supports an out-of-band mode (`conversation: "none"`), a custom `input` array (including `input: []` to strip context), per-response `instructions`, and a `metadata` field for correlating responses to client events. The community-documented pattern for "make the model say something about new state now" is `response.create` with `instructions` (e.g., "Tell the user the call is nearing 5 minutes and ask if they want to continue"); staff/community note there is otherwise "no official guidance" distinguishing system-item vs instruction injection.
**Why it matters for Parcel:** This is the exact substrate the whisperer writes into. It validates the drafted mechanism (one system item into the session) as the documented-correct channel for the judge band, but it also exposes a distinction the draft doesn't make: an injected system item is *passive* (the model may or may not use it on its next turn), whereas `response.create` with instructions is *active* (forces an utterance). Scenario 2 ("reach the door, turn back, ask what's next") and the refusal in scenario 3 are active events; a battery/pose delta is passive.
**Design implications:** Give every forwarded item a `voice_now` bit. Always-forward terminals/refusals should ride `response.create` with explicit per-response instructions ("Tell the owner you reached the door; ask what to do next") — putting the directive at the point of generation sidesteps the mini model's weak compliance with stale session instructions (matches R4L/R5 observations). Judge-band items should land as silent system items. Use `metadata` to tag whisperer-originated responses so eval fixtures can distinguish them.

### 2. Context Summarization with the Realtime API (OpenAI Cookbook, 2025)
**What it does:** Production recipe for long realtime sessions. Key facts: audio input tokens run ~**10× text** for the same sentence; the realtime context is ~32k and "instruction adherence drifts" as it fills; the recipe triggers background summarization at a token threshold (2k demo, **20–32k production**), keeps the last 2 turns verbatim, injects the summary **as a SYSTEM item** — explicitly because assistant-role summaries "can cause the model to mistakenly switch from audio responses to text responses" — and deletes superseded items via `conversation.item.delete`. Sessions cap around 30 minutes; longer interactions require restart-with-summary.
**Why it matters for Parcel:** A companion dog session is exactly the long-running case. This is the only official artifact quantifying how fast a realtime session degrades and it hard-confirms two drafted choices (system role; injection rather than instruction rewriting). It also shows what the draft is missing: injected state items *accumulate*, and the sanctioned remedy is deletion of superseded items, not just dedup at inject time.
**Design implications:** Maintain a **single rolling status item**: when a new whisperer item lands, `conversation.item.delete` the previous one. Track `response.done` token counts and treat context pressure as an input to the judge threshold (raise the significance bar as the window fills). Budget for audio's 10× token burn when reasoning about how many injections a session can afford.

### 3. Horvitz — Principles of Mixed-Initiative UI (CHI 1999) & Attention-Sensitive Alerting (UAI 1999)
**What it does:** The foundational decision-theoretic account of when a system should interrupt a person: compute the expected utility of alerting now vs deferring, where the **cost of interruption is context-dependent** (inferred from user activity) and the **value of the information is time-decaying**. The Priorities/Notification Platform systems fused desktop, calendar, and acoustic signals into a Bayesian estimate of attentional state and only surfaced alerts whose expected value exceeded the inferred interruption cost.
**Why it matters for Parcel:** The three-band significance policy is a (good) discretization of exactly this framework — always-forward = alerts whose value dominates any interruption cost (safety, refusals), never-forward = value ~0, judge band = the expected-utility computation. What Horvitz adds that the draft lacks: the threshold should be **modulated by the listener's state**, not fixed. An owner mid-sentence, mid-task, or mid-conversation has a higher interruption cost than an idle one.
**Design implications:** Feed conversational/owner state (VAD activity, floor state, owner motion from `owner_state.json`) into the judge-band threshold: silence lowers the bar, active dialogue raises it. Add time-decay: a buffered delta that was significant 20s ago may be worthless now (the nav reason strings in proof_final.txt go stale fast). This is deterministic math that belongs in the local chain, not in Gemma.

### 4. Rosenthal, Selvaraj & Veloso — Verbalization: Narration of Autonomous Robot Experience (IJCAI 2016; + RO-MAN 2016 refinement)
**What it does:** The canonical "robot reports status conversationally" work, deployed on CMU's CoBot service robots. Defines a **verbalization space** with three axes — *abstraction* (raw ticks → landmarks → summary), *locality* (whole route vs region), *specificity* (one utterance vs detailed narrative) — and shows different users want different points in that space; a follow-up learns to move within the space from dialogue ("shorter," "more detail").
**Why it matters for Parcel:** It is the closest ancestor of the whisperer's output format problem: raw executor state (block classes, yield reasons) must be re-rendered at the right abstraction before a human hears it. It also maps directly onto scenarios 1–3: the *terminal verbalization* ("I'm on the sidewalk now," "I can't circle you — you're at the desk") is a chosen point in verbalization space, not a dump of the nav reason string.
**Design implications:** The Gemma judge shouldn't just score significance — when it forwards, it should also *render* the item at a fixed abstraction level (landmark-level, one clause). Keep raw reason strings (`block_class=KEEPOUT_PERSON_DESK`) out of the hosted context; forward the verbalized form. Support owner tuning by dialogue ("stop narrating" / "tell me more") as a threshold/abstraction knob, which the deterministic layer applies.

### 5. Park et al. — Generative Agents (UIST 2023)
**What it does:** The most-cited agent-memory design. Every observation enters a memory stream with an **LLM-rated importance score (1–10) assigned at write time**; retrieval ranks by recency (exponential decay) × relevance (embedding similarity) × importance; periodic *reflection* synthesizes accumulated low-level observations into higher-level statements when summed importance crosses a threshold. Equal-weight composite beat any single signal.
**Why it matters for Parcel:** Direct precedent for "cheap local model scores accumulated state deltas": a small LLM assigning a bounded integer importance score at event time is a validated, load-bearing pattern in the field. The *reflection threshold* — act when **accumulated** importance crosses a bar, not on each item — is precisely the right shape for the judge band's delta buffer, and argues for scoring the *buffer sum*, not just the max item.
**Design implications:** Have Gemma emit a small structured score vector (novelty, urgency, task-relevance, 1–10 each) per buffer flush; keep the threshold arithmetic and recency decay in deterministic code so it's auditable and calibratable offline. Calibrate thresholds with the Qwen3-32B AutoRater against the 25 realtime_convo_v1 fixtures (which forwards would a human have wanted?).

### 6. Liu et al. — Proactive Conversational Agents with Inner Thoughts (CHI 2025)
**What it does:** Instead of reacting to turn-taking cues, the agent runs a **continuous covert stream of "thoughts" in parallel** with the overt conversation and computes an **intrinsic motivation score** per thought; it speaks only when motivation crosses a threshold at an appropriate moment. Formative study (n=24) plus evaluations showed gains in anthropomorphism, coherence, and turn-taking appropriateness over reactive baselines. (Related 2025 work, DiscussLLM, trains models directly on the binary "should I speak now?" decision.)
**Why it matters for Parcel:** This is architecturally *the whisperer*: a parallel cheap process forming candidate contributions and gating them by a motivation threshold, with the conversation channel left clean. It's strong evidence the two-model split (local scorer + hosted speaker) is not a hack but the emerging best practice for proactive agents. It also frames scenario 4 correctly: "owner is walking, not running" is a covert thought whose motivation (task-relevance + goal conflict) is high, so it should surface as a question.
**Why-to-speak vs what-to-know matters:** their central finding is that *timing* appropriateness drives perceived intelligence more than content quality.
**Design implications:** Score not only "is this significant" but "is this a *speakable moment*" — the floor-gated narration channel gives the mechanism; the judge should emit speak-now vs context-only as part of its verdict. Log suppressed thoughts; they're free training data for threshold calibration.

### 7. Ren et al. — Robots That Ask For Help / KnowNo (CoRL 2023, best paper)
**What it does:** Uses conformal prediction over an LLM planner's multiple-choice next-step distribution to give **statistical guarantees on when the robot should stop and ask a human**: if the calibrated prediction set is not a singleton, the robot is formally "uncertain" and triggers help-seeking, minimizing unnecessary questions while bounding task failure.
**Why it matters for Parcel:** Scenarios 2, 3, and 4 are all ask-vs-act decisions ("ask what to do next," "refuse and say why," "ask whether to just walk"). KnowNo's core lesson: asking should be triggered by a *calibrated, principled* uncertainty/ambiguity signal, not by prompt-vibes in the hosted model — which matters double given the mini model's observed weak instruction compliance. The deterministic chain already detects the objective condition (owner seated → orbit infeasible; owner gait ≠ commanded gait); the literature says surface these as **explicit ask/refuse events**, not as ambient context the voice model might act on.
**Design implications:** Add an "ambiguity/conflict" event class to the always-forward band, produced by the local chain (plan admission or navigator), each carrying a machine-generated question or refusal reason. Voice them via `response.create` instructions. Never rely on the mini model to *infer* that it should ask.

### 8. Packer et al. — MemGPT: Towards LLMs as Operating Systems (2023)
**What it does:** Treats the LLM context window as RAM and external stores as disk, with the model (or system) paging information in and out via function calls; introduces the **event vs heartbeat** distinction — the agent's loop is driven by discrete events (messages, timers, state changes) rather than continuous polling, and memory pressure triggers summarization/eviction. Evolved into Letta with asynchronous "sleep-time" memory consolidation.
**Why it matters for Parcel:** Frames the whisperer as an OS interrupt controller: per-tick telemetry is polled state (never enters the "CPU"), the judge band is an interrupt coalescer (buffer + threshold + rate cap), and always-forward events are NMIs. It also supplies the missing eviction half: a long session needs old status pages swapped *out* (delete/summarize), not just new ones rationed in.
**Design implications:** Adopt the interrupt-coalescing vocabulary in the design doc — it makes the rate caps and dedup principled rather than ad hoc. Consider a "sleep-time" Gemma pass that consolidates the session's state history into the single rolling status item during conversational lulls.

### 9. Chroma Research — Context Rot (Hong, Troynikov, Huber, 2025)
**What it does:** Evaluated 18 frontier models and showed performance degrades **non-uniformly and well before the advertised window limit** as input grows; **distractors** — plausible but wrong/stale content near the needle — are among the strongest degraders; semantically similar distractors hurt most. A 200k window can lose serious accuracy by 50k real tokens.
**Why it matters for Parcel:** The empirical case for the never-forward band and the hard caps. Every stale status item left in the realtime session is a distractor of exactly the worst kind: semantically near-identical to the current state but wrong ("position: hallway" three items above "position: sidewalk"). With audio at 10× token cost and a 32k window, an unpruned status log is the fastest possible route to the instruction-adherence drift already observed on the mini model.
**Design implications:** Supersede, don't append (delete prior status items); keep injected items short and schema-stable; treat total injected-status tokens per session as a budgeted resource with its own cap, separate from the rate cap.

### 10. Proactive HRI timing studies & full-duplex models (2020–2026)
**What it does:** "Building Proactive Voice Assistants: When and How (not) to Interact" (arXiv 2020, industrial prototype + user study) proposes a framework for when a home voice device may self-initiate, centered on "right information, right way, right time" and the annoyance/privacy cost of misfires. HRI 2026's "Desirability of Proactive Robots" found **more than half of users prefer reactive (person-initiated) interaction**, though *collaboration outcomes* were best with proactive robots, and users want control over initiation; frequency studies (Sci. Reports 2026) show utterance frequency directly drives annoyance. Users do, however, prefer robots that **proactively communicate their own capabilities and limitations**. Meanwhile full-duplex dialogue models (Moshi, Kyutai 2024; 2026 turn-taking analyses) show when-to-speak can be learned end-to-end — but only with dual-stream audio architectures Parcel's hosted half-duplex model doesn't have, so the decision must live outside the model.
**Why it matters for Parcel:** Calibrates the default posture: a companion dog should be **quiet by default**, proactive mainly about its own limits/refusals (scenario 3's "SAY you cannot") and terminals (scenario 2), with everything else reactive or silent-context. It also confirms the architectural necessity of the whisperer: gpt-realtime-2.1-mini cannot itself learn Moshi-style silence, so an external gate is not optional.
**Design implications:** Make capability/limit announcements (refusals, degraded modes) the *most* privileged voice-now class — the one proactive category users reliably want. Keep the judge-band voice-now output rare (order: a few per session, not per minute) and give the owner a spoken control over narration level.

## Design pressure

**What the drafted design gets right (per this literature):**
- **The three-band split is the canonical solution shape.** It discretizes Horvitz's expected-utility alerting, matches Inner Thoughts' covert-thought-plus-threshold architecture, and matches the field's convergence (Generative Agents' LLM importance scoring; LiveKit/Pipecat production guidance of "background LLM silently injects dense summaries into chat context").
- **System-role injection is documented-correct**, with a specific, non-obvious payoff: the cookbook warns assistant-role injections can flip the realtime model from audio to text mode. The draft dodges a real production failure.
- **Hard rate caps and dedup outside the judge** are strongly supported: context-rot results show distractor accumulation degrades models non-uniformly, and LLM importance scores are noisy (Generative Agents), so deterministic caps must bound a miscalibrated judge. Keeping the caps out of Gemma keeps them auditable.
- **A cheap local intermediary is precedented, not exotic** — it's Inner Thoughts' covert stream, MemGPT's memory manager, and the production sliding-window-plus-background-summarizer pattern, all in one.

**What it gets wrong or is missing:**
1. **It conflates "inject" with "speak."** The single biggest gap. The literature and the API both separate *context* (silent system item, consumed on next turn) from *initiative* (`response.create` with instructions, forces an utterance). Terminals, refusals, and ask-events (scenarios 2–4) need forced voicing with the directive placed in the `response.create` instructions — especially given the mini model's measured weak compliance with passive context. Judge-band items should default to silent. Every forwarded item needs a `voice_now` bit and refusals/asks should carry pre-rendered question text from the local chain (KnowNo: asking must be triggered by calibrated local signals, not hoped-for inference in the hosted model).
2. **No supersession/eviction.** Dedup at inject time still leaves a growing log of stale status items — semantically-similar distractors, the worst kind per context rot, inside a 32k window burning audio tokens at 10×. Adopt the cookbook pattern: one rolling status item, `conversation.item.delete` the predecessor; consider periodic consolidated re-summarization during lulls.
3. **Fixed thresholds ignore interruption cost.** Horvitz and the HRI studies say the judge-band bar must move with listener state: raise it while the owner is speaking/engaged or mid-activity, lower it in silence. The floor gate handles collision, not desirability — a technically non-colliding status remark during the owner's focused work is still the annoyance the HRI frequency studies measure. Also add time-decay so buffered deltas expire instead of arriving late.
4. **Injected-item format is unspecified, and the model is wording-sensitive.** The Realtime Prompting Guide documents extreme sensitivity to phrasing (bullets > prose, CAPITALIZED key rules, single-word swaps changing behavior). Free-form Gemma prose risks (a) the model reading the item aloud verbatim, (b) persona drift as instruction-bearing system items accumulate and dilute the session prompt (the cookbook's "instruction adherence drift"). Use a rigid template — e.g. `[ROBOT STATUS — CONTEXT ONLY, DO NOT READ ALOUD] pos=sidewalk; task=idle; note=...` — rendered at a fixed verbalization abstraction (Rosenthal/Veloso), never raw reason strings.
5. **No offline calibration loop is drafted, but the assets exist.** Generative Agents shows LLM importance scores are usable but need weighting; the right move is Gemma emitting a structured score vector with deterministic thresholding, calibrated by the Qwen3-32B AutoRater against the 25 captured fixtures — including two metrics the draft doesn't name: *non-sequitur leakage* (model mentions injected state apropos of nothing) and *missed-forward regret* (a human rater would have wanted the update).
6. **Unconsidered pitfalls:** (a) forced `response.create` racing owner barge-in — the floor gate must be able to cancel an in-flight whisperer response, not just defer new ones; (b) session lifetime — realtime sessions cap ~30 min, so the whisperer design needs a restart-with-summary story where the rolling status item is part of the handoff; (c) out-of-band responses (`conversation: "none"`) are an unused tool — e.g., for having the hosted model privately reconcile state without polluting the conversation; (d) users' strongest documented preference is for robots that proactively announce *limitations* — so the scenario-3 refusal channel is not an edge case but the flagship proactive behavior, worth its own eval fixtures.

**Cadence answer (focus question):** the literature's converged answer is *event-driven, not periodic*. No prominent system injects on a timer; all gate on significance with deterministic caps, and the HRI data says default-quiet with proactive voice reserved for terminals, refusals/limits, and calibrated asks — roughly "a few self-initiated utterances per session," with silent context updates bounded by supersession rather than frequency alone.
