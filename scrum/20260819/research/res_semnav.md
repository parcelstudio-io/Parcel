# Literature sweep: semantic navigation, arrival/affordance common sense, social positioning

Angle: goal semantics ("on" vs "near"), termination criteria, affordance-aware goal sampling, graceful refusal, socially-aware positioning. ## 1. LM-Nav (Shah, Osiński, Ichter, Levine — CoRL 2022)
**What it does:** Zero-shot instruction-following outdoor navigation built entirely from frozen pretrained parts: GPT-3 parses the instruction into an ordered landmark list, CLIP grounds each landmark phrase against images at nodes of a self-built topological graph, and ViNG (a learned image-goal policy) drives between nodes. No language-annotated robot data, real robot, long-horizon outdoor routes. ([arXiv:2207.04429](https://arxiv.org/abs/2207.04429))

**Why it matters for Parcel:** This is the canonical "LLM proposes, engineered pipeline disposes" split — exactly Parcel's hosted-realtime-model-proposes / local-chain-commands architecture. Crucially, its arrival semantics are *engineered by retrieval*: "arrive at the sidewalk" means "reach the graph node whose image best CLIP-matches 'sidewalk'." That yields *near/at-view-of* semantics, never *on-top-of* — it cannot distinguish standing beside the sidewalk from standing on it. Owner scenario (1) is precisely the failure class LM-Nav's formulation cannot express.

**Design implications:** Landmark/label-level grounding (Parcel's `navigate_to("sidewalk")` string goal is the same shape) needs an added *relation* layer. The goal must carry a spatial predicate (`inside`/`near`/`facing`), and the local navigator — not the hosted model — must evaluate it. Parcel's plan IR already has the field; the literature says the evaluation of it is the hard, engineered part.

## 2. NavGPT (AAAI 2024) and NavGPT-2 (ECCV 2024) — Zhou, Hong, Wu et al.
**What it does:** NavGPT runs GPT-4 as a pure zero-shot navigator: textual scene descriptions in, discrete action (including STOP) out, with explicit chain-of-thought; it underperforms trained VLN specialists by a wide margin. NavGPT-2 fixes the gap by freezing a VLM for reasoning/communication and handing action selection (and stopping) back to a *trained navigation policy network*. ([NavGPT](https://arxiv.org/abs/2305.16986), [NavGPT-2](https://arxiv.org/abs/2407.12366))

**Why it matters for Parcel:** Direct experimental evidence on the focus question: **prompted arrival/stop decisions from an LLM are unreliable; prominent systems moved termination into trained or engineered components while keeping the LLM for language.** This is the same lesson Parcel observed empirically — R4L/R5 status docs record the gpt-realtime-2.1-mini's weak instruction compliance (ability over-claims, the unfixed two-beat tool turn). If a full GPT-4 with curated textual observations can't stop well, a mini realtime voice model narrating a mission absolutely should not own "am I on the sidewalk yet."

**Design implications:** Keep the hosted model strictly at intent level; never let a tool-call argument encode termination (e.g., no "stop when close" free-text). NavGPT's other useful precedent: it used a *GPT-3.5 history summarizer* to compress navigation history for the expensive model — published precedent for Parcel's whisperer (cheap local Gemma compressing state deltas for the hosted session).

## 3. ObjectNav Revisited (Batra, Gokaslan, Kembhavi, Mousavian, Mottaghi, Savva, Toshev, Wijmans — 2020)
**What it does:** The community-standard *definition paper* for object-goal navigation success: agent must emit STOP, be within a **1.0 m Euclidean shell measured from the object's surface** (not centroid), and the object must be **visible/viewable from the stopping point** (oracle visibility check). It exists because earlier ad-hoc criteria (geodesic to centroid, no visibility) produced agents that "succeeded" behind walls. ([arXiv:2006.13171](https://arxiv.org/abs/2006.13171))

**Why it matters for Parcel:** This is the clearest statement in the field that **goal semantics are an engineered evaluation contract, not a learned or prompted behavior** — and that the naive contract (distance to a point) is wrong in ways that exactly parallel owner scenario (1). Distance-to-surface vs distance-to-centroid, plus a perceptual verification condition at stop, is the ObjectNav community's hard-won correction. Parcel's live proof shows the navigator tracking a scalar `goal=0.7` distance — if that is distance to a sidewalk point/centroid, Parcel will reproduce the pre-2020 failure mode: terminate *near* but not *on*.

**Design implications:** Define per-target-class success predicates in the task executive: **region goals → footprint containment** (robot's 0.32 m footprint fully inside the region polygon, with an edge margin), **object goals → surface-shell distance + visibility**, **person goals → social-zone shell** (see #10). Success must be *verified against perception at stop* before the mission is declared arrived to the voice model.

## 4. GOAT: GO to Any Thing (Chang, Gervet, Chaplot et al. — Meta/CMU/UIUC, 2023) + GOAT-Bench (CVPR 2024)
**What it does:** A production-grade modular lifelong navigation system (deployed across 9 homes, multiple embodiments) that reaches goals specified as category, image, or language description. Core: a continually-augmented **instance-aware semantic memory** that stores object instances with viewpoints, a modular mapper/planner, and fixed distance-threshold success. GOAT-Bench standardizes the multimodal lifelong benchmark. ([GOAT](https://arxiv.org/pdf/2311.06430), [GOAT-Bench](https://arxiv.org/abs/2404.06609))

**Why it matters for Parcel:** The strongest recent evidence that at deployment scale, major labs chose **modular + engineered** over end-to-end or prompted: perception, memory, goal resolution, and termination are all deterministic modules; no LLM in the motion loop. It also demonstrates why instance memory matters for a *companion*: "the door" and "the desk" are persistent instances in the home; lifelong memory turns second visits from search into direct navigation. Maps to owner scenarios (2)/(3) (door, desk are remembered instances) and to `recall_memory`.

**Design implications:** Parcel's semantic search (`search_entity_frontier` in the live proof) should write found instances into a persistent instance map keyed by class + location + viewpoints, so "get to the door" is resolvable without re-search and so the whisperer can report semantically ("reached the front door" not "reached (3.4, 1.2)").

## 5. Semantic frontier exploration: VLFM (ICRA 2024), ESC (ICML 2023), L3MVN (IROS 2023)
**What it does:** Three flagship zero-shot object-nav systems that choose *which frontier to explore* using language/commonsense: VLFM builds a BLIP-2 value map over frontiers and — critically — **switches to a deterministic point-goal controller the moment an object detector confirms the target, stopping at an engineered threshold**; deployed on Boston Dynamics Spot. ESC converts LLM commonsense (object-room co-occurrence) into *soft logic predicates* over frontiers; L3MVN has an LLM score textual descriptions of frontier surroundings. ([VLFM](https://arxiv.org/abs/2312.03275), [ESC](https://proceedings.mlr.press/v202/zhou23r.html), [L3MVN](https://github.com/Rongtao-Xu/Awesome-LLM-EN))

**Why it matters for Parcel:** The consistent architecture across all three: **language models bias exploration; they never decide arrival.** Detection → geometric goal → engineered stop. Parcel's searching-state (`scan_behavior_rotate`, `semantic_search_scan`, `search_entity_frontier` in the proof) is exactly this pipeline, and the literature endorses inserting cheap semantic scoring (local Gemma could play ESC's role) at the frontier-selection point only. ESC's "soft commonsense as constraints on a deterministic planner" is also the correct formal shape for common-sense rules like "sidewalk goals must terminate inside the sidewalk mask."

**Design implications:** If "go to the sidewalk" search stalls (proof shows searching resuming at t=96s after repeated person-blocks), Gemma-scored frontier priors ("sidewalks are adjacent to roads, away from building interiors") are the literature-standard cheap upgrade — a bounded, offline-scoreable query, same infrastructure as the whisperer's judge band.

## 6. Last-mile navigation: SLING (CoRL 2022) + REALM / "Last-3-Meter Grounding Gap" (2026)
**What it does:** SLING showed ~10–12% of all image-goal/object-goal failures are *last-mile*: goal already found, agent fails to close the final meters or stop correctly, and fixed it with a dedicated geometric last-mile module. The 2026 REALM work names the "Last-3-Meter Grounding Gap" in VLN: standard success (stop within 3 m) ignores **final orientation and target visibility**; it proposes instance-centric metrics (proximity precision, target visibility, final-view grounding) and a plug-in visibility-aware stopping module, improving four VLN backbones. ([SLING](https://arxiv.org/abs/2211.11746), [REALM](https://arxiv.org/pdf/2607.03792))

**Why it matters for Parcel:** This sub-literature *is* the owner's scenario (1) and half of scenario (2): the field measured that ending "somewhere near" is a distinct, large failure class, and that the fix is a **dedicated terminal phase** — a different controller/checker for the final approach, with visibility and orientation in the success predicate. Scenario (2)'s "turn back to the owner" is literally a final-orientation requirement, which REALM shows must be explicit because no distance criterion induces it.

**Design implications:** Add a terminal `Arrive` micro-phase to the task executive: refine pose until the goal predicate holds (containment / surface shell), then execute a *post-arrival orientation policy* per goal class — region: face along travel direction; object/door: face target at standoff; any owner-issued mission: end by reorienting toward the owner and emitting a "what next?" terminal event. That terminal event is an always-forward item for the whisperer.

## 7. VLN surveys + ULN (Gu et al. ACL 2022; "VLN Today and Tomorrow" TMLR 2024; ULN EMNLP 2022)
**What it does:** The surveys codify the task families and the metric conventions (R2R/REVERIE success = stop within **3 m** of goal viewpoint; SPL; oracle-stop gaps showing agents find goals they fail to stop at) and name **instruction ambiguity and underspecification** as a top open problem in the foundation-model era. ULN attacks it directly: real instructions are multi-level underspecified ("get to the door" gives no post-arrival intent); its framework classifies instruction granularity and uses grounding uncertainty to switch exploitation↔exploration. ([Gu survey](https://aclanthology.org/2022.acl-long.524/), [TMLR 2024 survey](https://www.researchgate.net/publication/382111280_Vision-and-Language_Navigation_Today_and_Tomorrow_A_Survey_in_the_Era_of_Foundation_Models), [ULN](https://arxiv.org/abs/2210.10020))

**Why it matters for Parcel:** Two things. First, the 3 m convention means *most VLN results say nothing about "on top of"* — benchmark-derived intuitions will not give Parcel scenario-(1) behavior for free; region containment is stricter than anything mainstream VLN measures. Second, the surveys legitimize treating **underspecification as a first-class state**: "get to the door" (scenario 2) and "run with me" while walking (scenario 4) are underspecified instructions, and the literature's answer is to detect the underspecification level, not guess.

**Design implications:** The intent router should tag missions with a specification level (fully specified / goal-only / ambiguous-parameter). Goal-only missions get a default post-arrival behavior of *return-attention-and-ask* — which Parcel can implement deterministically since `AskClarification` is already an admitted skill.

## 8. KnowNo — Robots That Ask For Help (Ren et al., Princeton/Google DeepMind — CoRL 2023, best-paper)
**What it does:** Uses conformal prediction over an LLM planner's option likelihoods to decide *when to ask for help vs act*, with a statistical guarantee: calibrated task-success rate at minimal asking. Handles spatial ambiguity, preference ambiguity, and infeasibility across real robot tasks. ([arXiv:2307.01928](https://arxiv.org/abs/2307.01928), [site](https://robot-help.github.io/))

**Why it matters for Parcel:** The owner's scenarios (2), (3), (4) all end in a speech act — ask, refuse-and-explain, ask — and KnowNo is the prominent treatment of *when* those speech acts should fire. Its two principles map directly: **calibrated confidence** (ask when genuinely ambiguous — owner walking while saying "run with me") and **minimal help** (don't ask when unambiguous — an over-chatty companion that confirms everything is a real failure mode; the proof already shows the voice lane repeating near-identical "someone is in my way" pleas 4 times in 100 s). It also frames the Gemma judge band: an uncalibrated local judge deciding "significant / not significant" is exactly the un-aligned-uncertainty problem KnowNo solves.

**Design implications:** (a) Make ask-vs-act thresholds *calibrated, not vibes*: use the 25 captured threads in `evals/companion/realtime_convo_v1/fixtures/` plus the Qwen3-32B AutoRater as a calibration set for both the router's clarify-threshold and the whisperer's forward-threshold. (b) Rate-limit repeated help requests with escalation (new information or silence), not repetition.

## 9. SayCan (Ahn, Brohan, Ichter et al., Google — CoRL 2022)
**What it does:** Grounds LLM task proposals in **learned affordance functions**: for each skill, a value function estimates success probability from the current state; the executed skill maximizes (LLM usefulness × affordance feasibility). Grounding nearly doubled long-horizon performance over ungrounded LLM planning. ([arXiv:2204.01691](https://arxiv.org/abs/2204.01691))

**Why it matters for Parcel:** SayCan is the citation for Parcel's plan-admission stage — and for scenario (3) specifically. "Circle around me" is a *proposal* whose affordance ("Can") must be scored against geometry: is an orbit annulus of radius r around the owner traversable, or is the owner seated flush to a desk so the annulus is blocked? SayCan says the feasibility check is a separate, non-linguistic model/computation, and the composition (proposal × feasibility) is where refusal originates. A refusal produced *by the admission stage with a machine-readable cause* is also what lets the robot **say why** ("I can't walk around you — the desk blocks my path"), which SayCan-style systems surface naturally because the failed affordance is explicit.

**Design implications:** Implement `OrbitOwner` admission as a geometric affordance test: sample the orbit circle at the requested radius against the costmap + person keepout + activity space (see #10); on failure, emit a structured refusal `{skill, cause: "orbit_annulus_blocked", blocking_entity: "desk"}` that the local chain templates into speech — do not rely on the mini model to compose an accurate refusal from raw state (R5 documented its ability over-claims).

## 10. From Proxemics Theory to Socially-Aware Navigation (Rios-Martinez, Spalanzani, Laugier — IJSR 2015) + HRI approach studies
**What it does:** The standard survey mapping human spatial-social science into robot navigation costs: Hall's proxemic zones (intimate <0.45 m / personal 0.45–1.2 m / social 1.2–3.6 m), **F-formations** (the o-space of an interacting group must not be crossed), **activity spaces** (the region between a person and the object they are using — e.g., a person at a desk, a viewer and a screen — is socially occupied even when physically empty), and **affordance spaces** (regions others may need). Companion HRI studies: people dislike frontal approach from behind-of-attention; seated people prefer side approaches; stopping distance ≈ personal zone. ([survey](https://link.springer.com/article/10.1007/s12369-014-0251-1), [approach studies](https://www.tandfonline.com/doi/full/10.1080/09540090600879513))

**Why it matters for Parcel:** This survey contains the *precise concept* the owner's scenario (3) needs: a person sitting at a desk is in an F-formation/activity-space engagement with the desk; a correct social robot treats the person-desk region as impassable and the orbit as **socially infeasible even where geometrically feasible**. It likewise gives scenario (2) its numbers: "go near the door / near a person" should terminate in the social or personal zone with an orientation that establishes an F-formation with the owner (face them, don't loom). And person-yield distances (visible throughout the proof's `person_slow`/`person_stop` bands) should be proxemics-derived, not a single radius.

**Design implications:** Add to the world model: per-person engagement state (standing / walking / seated-engaged-with-object) and derived keepout geometry (proxemic ellipse + activity-space polygon toward the engaged object). Orbit admission (#9) tests against this. Person-goal standoffs default to ~1.2 m (near edge of social zone), approach path curved to enter the person's field of view.

## 11. Social robot navigation at large: Principles & Guidelines (Francis et al. 2023, 31 authors incl. Google DeepMind/NVIDIA/Stanford) + Core Challenges survey (Mavrogiannis et al. 2023)
**What it does:** A cross-institution consensus paper defining what social navigation *is* and how to evaluate it: principles of safety, comfort, **legibility**, politeness, **social competency** (following conventions: doorways, queues, not blocking passages), understanding-of-other-agents, and **contextual appropriateness**, with benchmarking guidance; Mavrogiannis et al. taxonomize the field's core challenges. ([Principles](https://arxiv.org/abs/2306.16740), [taxonomy survey](https://arxiv.org/pdf/2311.06922))

**Why it matters for Parcel:** Gives the vocabulary and evaluation frame for the whole companion project — and specifically blesses two things Parcel already does: (a) yielding/stopping for people over pushing through (safety > progress; the proof's refusal to push past is textbook), and (b) *narrating* blocks (legibility: robots should make their state and intent understandable). It also covers portal conventions relevant to scenario (2): stopping *in* a doorway violates social competency — "get to the door" must terminate offset from the swing/traffic zone, not on the threshold.

**Design implications:** Encode door goals as "near-door standoff pose, out of the swing arc and traffic lane, facing owner." Adopt the paper's evaluation axes as AutoRater rubric dimensions for the companion evals (comfort, legibility, contextual appropriateness) — Parcel's Qwen judge harness is well-placed to score transcripts against them.

## 12. CoNVOI (Sathyamoorthy et al., UMD GAMMA — IROS 2024) and side-by-side accompaniment (Morales et al. 2014; Follow-Bench 2025)
**What it does:** CoNVOI uses a VLM zero-shot to identify navigation *context* (sidewalk, crosswalk, corridor) and produce a reference path obeying contextual conventions — literally prompting "stay on the pavement" — with a local planner executing and a cheap check (is the extrapolated point still on pavement?) gating VLM re-queries. Morales' side-by-side walking model (and successors, benchmarked in Follow-Bench 2025) formalizes companion locomotion: anticipate both partner and self, match pace, maintain formation even without knowing the destination. ([CoNVOI](https://arxiv.org/abs/2403.15637), [Morales](https://www.researchgate.net/publication/265551540_Walking_Together_Side_by_Side_Walking_Model_for_an_Interacting_Robot), [Follow-Bench](https://arxiv.org/pdf/2509.10796))

**Why it matters for Parcel:** CoNVOI is the closest published system to scenario (1)'s semantics: "on the sidewalk" as a *contextual containment convention* enforced by checking path points against a semantic surface mask — cheap, deterministic, VLM only consulted at context changes (a structural cousin of the three-band whisperer: expensive model consulted sparsely, deterministic gate decides when). The side-by-side line is scenario (4): pace matching is a *continuous formation controller* with anticipation, and pace *mismatch* (owner walking during "run with me") is a detectable formation-parameter conflict — the natural trigger for a clarify event, not something the hosted model should infer from narration.

**Design implications:** (a) Maintain a semantic surface mask (sidewalk/road/grass) in the local map; region-goal success = footprint containment in mask; the same mask powers the existing `avoid_road_when_not_crossing` invariant. (b) `FollowFormation` should expose commanded-pace vs owner-observed-pace; sustained mismatch beyond a band emits a `formation_conflict` event routed to `AskClarification` — deterministic detection, voice model only voices it.

# Design pressure

**What the drafted design gets right (strongly literature-aligned):**
- **Motion authority in a deterministic local chain, hosted LLM as proposer.** This is the consensus architecture of every prominent deployed system surveyed (LM-Nav, GOAT, VLFM, SayCan, CoNVOI). NavGPT→NavGPT-2 is a published ablation showing why: prompted spatial/termination decisions underperform; the field retreated to engineered stopping. Parcel's own R4L/R5 observations of mini-model weak compliance independently replicate this.
- **Plan admission as a distinct stage** is SayCan's Say/Can composition; `effective_invariants` and the person-yield policy match the social-nav consensus principles (safety, yielding, legibility-through-narration).
- **The three-band whisperer is structurally sound.** Deterministic always/never bands wrapping a learned judge is the same "deterministic guardrails around a model" pattern as SayCan's affordance gating and CoNVOI's re-query gate; NavGPT's GPT-3.5 history summarizer is direct precedent for a cheap LM compressing state for an expensive one. Hard rate caps and dedup *outside* the judge is the correct polarity — never let the model open the valve.

**What it gets wrong or leaves at risk:**
1. **Region-goal termination is underspecified and currently point-shaped.** The live plan IR says `relation:"inside", tolerance_m:0.0`, but the navigator tracks a scalar goal distance (`goal=0.7` in the proof). ObjectNav Revisited is the field's cautionary tale: distance-to-a-point criteria certify "near, not on." "Inside" must be evaluated as footprint containment in a semantic surface mask (CoNVOI-style), with margin from region edges — and `tolerance_m:0.0` against a polygon is fine, but against a sampled point it is meaningless.
2. **No perceptual verification at stop.** ObjectNav's visibility condition and REALM's last-3-meter metrics (proximity + visibility + final orientation) say arrival must be *confirmed against perception* before being declared. Parcel should not tell the voice model "arrived at sidewalk" until the containment/visibility predicate has been re-checked at the stop pose. Otherwise the whisperer forwards a false terminal — the worst possible item to forward.
3. **Final orientation is missing from the goal predicate.** Scenario (2)'s "turn back to the owner and ask" is a final-pose requirement plus an ask-terminal. Literature (REALM, F-formations, approach studies) treats end orientation as part of success, not a courtesy. The drafted design's terminal events should carry pose intent, and goal classes need post-arrival orientation policies (region → travel heading; door → offset standoff out of swing arc, facing owner; person → social-zone standoff entering their field of view).
4. **Refusal needs a geometric-social affordance test with a machine-readable cause.** Scenario (3) is not an NLU problem: orbit feasibility = orbit annulus clear in the costmap AND not crossing the owner's activity space (person-seated-at-desk is the survey's canonical activity-space example). The refusal utterance should be templated locally from the failed-affordance cause; given the mini model's documented over-claiming, letting it improvise "why I can't" risks fabricated reasons.
5. **Ask-vs-act thresholds are uncalibrated.** KnowNo's whole point: asking behavior should be calibrated to a target success rate on a held-out set, else the companion is either presumptuous or nags. Parcel has the exact ingredients (25 fixture threads, Qwen3-32B AutoRater) to calibrate both the router's clarify-threshold (scenario 4) and the Gemma judge's forward-threshold — treat the judge band as a binary classifier and calibrate its operating point, don't hand-tune the prompt.

**What the literature says is missing entirely:**
- **A goal-predicate vocabulary as the tool contract.** `navigate_to(target)` should become `navigate_to(target, relation, standoff_class)` with a small closed set (`inside | near | at_entrance | beside_person | facing`), resolved to per-class predicates locally. Every surveyed system that handles arrival well made the predicate explicit somewhere engineered; none infers it per-episode from free text at execution time. The hosted model's only new job — mapping "on the sidewalk"→`inside`, "get to the door"→`at_entrance` — is a language task squarely within even a mini model's competence, and it fails safe (local defaults per target class).
- **Persistent instance memory** (GOAT): doors, desks, the sidewalk edge should be remembered instances, making repeat commands direct and giving the whisperer semantic names to narrate.
- **Person-engagement state in the world model** (proxemics survey): standing/walking/seated-engaged, with derived activity-space keepouts. Needed for orbit admission, approach paths, and yields around seated people.
- **Formation-conflict detection** for follow modes (Morales/Follow-Bench): commanded-pace vs observed-owner-pace mismatch as a deterministic clarify trigger for "run with me."

**Pitfalls not yet considered:**
- **Oscillation flooding the judge band.** The proof shows `blocked↔navigating` flapping at ~1 s period for 80 s and four near-identical voice pleas. Without hysteresis/debounce *before* the delta buffer, the judge band's budget is consumed by one standing pedestrian, and the voice model repeats itself — a legibility failure (escalate or stay silent; never re-say). Dedup should be *semantic-state* dedup (same block class + same goal ⇒ one item until class changes), which the mission-log ring's "+N more changes" collapsing already half-implements.
- **Region names that are directions, not places.** "Sidewalk" in an urban scene is multi-instance and unbounded; frontier search for "sidewalk" can succeed on the *wrong* sidewalk. Instance memory + "nearest instance satisfying the relation" disambiguation is the GOAT-style fix.
- **The judge itself hallucinating significance.** Score *structured* delta records (block-class transitions, invariant firings, distance milestones), never free-text summaries of raw telemetry; keep the judge's output a scalar/enum so it cannot inject content into the hosted session — only select which pre-templated item goes through the floor-gated narration channel.
- **Asking at the wrong turn boundary.** The realtime lane's known two-beat tool-turn defect (R5, unfixed) means an injected ask-terminal can interleave badly with an in-flight response; ask-terminals should be always-forward but *floor-gated behind turn completion*, which the narration channel's floor gate must actually check.

**Bottom line on the focus question:** across LM-Nav, GOAT, VLFM/ESC/L3MVN, SLING/REALM, and CoNVOI, arrival semantics in prominent systems are **engineered** (predicates, thresholds, masks, verification), occasionally **learned** as a dedicated stopping/last-mile module (NavGPT-2, SLING, ULN), and essentially **never successfully prompted**. Refusal and asking are handled as calibrated, structured decisions (KnowNo, SayCan) with the language model voicing — not making — the call. Parcel's drafted architecture points the same way; the gaps are the goal-predicate vocabulary, stop-time verification, final orientation, social-affordance admission for person-relative maneuvers, and calibration + debouncing around the whisperer's judge band.
