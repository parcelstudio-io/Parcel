## Verdict

ENDORSE B as target, A as mandatory degraded mode, C-learned-ranker deferred — but REFRAME the decision. Grounded in the tree, B is not an open 3-way choice; it is the already-shipped architecture. src/parcel_robot/instructnav/arbiter.py (ProposerBus emits SE2Goal|None, never velocity; GoalArbiter vetoes TTL+lethal and hands one winner to grid_v1), src/parcel_robot/core/arbiter.py (CommandArbiter is 'the only gate through which runtime velocity commands may pass', with emergency latch), src/parcel_robot/brain/executive.py (replace() requires strictly-increasing plan_revision; report() ignores stale revisions), and src/parcel_robot/instructnav/siglip2_onnx.py (real SigLIP-2, opt-in via PARCEL_SIGLIP2_ONNX, string fallback when off) already implement B's propose/dispose boundary, and A is literally that same code with proposers/SigLIP disabled. So 'pick B' ratifies reality; it is the RIGHT boundary (relax the learned surface exactly at language/task/goal PROPOSAL, keep metric path + body command + final safety classical — matching where the measured residual lives and where it demonstrably does not, i.e. trajectory generation). The core reason to reframe: the load-bearing deliverable is NOT the dual-system narrative but (1) the P0 authority corrections + ABI freeze and (2) three lanes the plan under-schedules against codebase reality — camera-as-ingress, cross-session memory, and a CI/eval runner. I credit the packet more than a pure 'relabel' charge: DESIGN_B section 4.2 gives a real falsifiable decision, and COMPARISON section 13.6 already says the next milestone is 'Phase 0 + Design A closed path, not model training' — the packet is not selling a model story, it is deferring one. Confidence: high, from direct source reading.

## Where we AGREE with Sol

- The propose/dispose incision is correct best practice AND correctly placed: learned systems propose task/goal/reaction as SE2 goals; classical code owns metric path, single body-velocity command, and final post-shaper safety. For a companion robot near people this is the right authority boundary, and it is exactly what ships today (arbiter.py ProposerBus -> GoalArbiter -> grid_v1 -> collision/reactive_safety -> CommandArbiter).
- A is a genuine mandatory degraded mode, not dead weight. It is B-with-models-off (soft-imported proposers -> None, SigLIP opt-in, string-fallback grounding), so it costs near-zero net-new work and provides the offline/no-GPU mode, the attribution oracle, and the commissioning path for free.
- Deferring Design C's LEARNED RANKER is correct. Its own activation preconditions (DESIGN_C section 1.3 / COMPARISON section 8.3) demonstrably fail now: grounding only just became real, the camera is not yet the ingress, and memory is thin, so the dominant failure mass sits upstream of candidate selection. Training a ranker now would be premature.
- The 'no model authors velocity/Sport' invariant is preserved at design level and in shipped code: proposers return SE2Goal|None, CommandArbiter is the single TTL-gated writer with emergency latch, and DESIGN_C section 3.1-3.3 makes the selector/ranker own no Unitree handle and forbids 'unmasking'.
- SHARED_FOUNDATION's abstractions are sound and match robotics practice: five-level authority lattice with data-down/authority-not-up, single-writer command lineage, freshness-join against ONE decision time, monotonic-clock discipline, independent terminal witness (feedback is not success), and keeping embodiment units like 'step' unexpanded until the trusted skill adapter reads the robot profile.
- Sequencing P0 correctness (fail-closed HOLD on stale sensing, exact-zero reassert after shaping, atomic lifecycle, one clearance convention) ahead of any model training is right; these are substrate defects, not intelligence deficits.

## Where we DIVERGE from Sol (with source evidence)

- Severity of P0-H is miscast. The dimensional bug is real in source (authority.py:616 adds person_latency_factor 1.4 x reaction_latency_s 0.12 = ~0.168 s onto a metres stop_distance; DESIGN_C line 173/204 flags it too), but it is LATENT, not a live hazard: the live brake is collision.py:106 (flat nearest_person_m < 1.2 m, where the 1.2 m social floor masks the buggy term at v=0) and the predictive obstacle term collision.py:140 / reactive_safety.py:86 are dimensionally valid (m + m/s*s). It also errs conservative (stops farther). So fix it, but rank it below P0-A (exact-zero after shaping) and P0-B (fail-closed). The real work Design C line 204 itself names is unifying the THREE parallel proximity consumers (authority.SafetyEnvelope / collision.CollisionPolicy / reactive_safety.ReactiveSafetyPolicy) onto one convention — partly done already (collision.py derives-by-reference, pinned by test_authority_family_equality.py).
- P0-C is genuine net-new, contra the 'redundant with executive plan_revision' read. executive.py already invalidates by strictly-increasing plan_revision and lease release, but instructnav/arbiter.py ProposerBus/GoalArbiter carry NO revision or channel_epoch and are not flushed by the executive transaction (DESIGN_C line 197 confirms: arbiter 'has no batch, trajectory mask, task revision, or learned rank contract'). B's P0-C text explicitly extends atomicity to model buffers — that flush is the actual missing piece.
- C's phasing is mildly circular but the fix is cheaper than the evaluators imply. COMPARISON 8.3 gate #3 (oracle replay shows a different existing candidate would have fixed failures) presupposes counterfactual tooling, yet the plan parks that tooling in Phase 4 after the gate is supposed to be measured. Pull forward ONLY the cheap offline subset — candidate logging + counterfactual-oracle replay in the eval harness — NOT C's full multi-candidate runtime ABI (WorldStateSliceV1/CandidatePoolV1/HardMaskVerdictV1/RankDecisionV1/CommitLeaseV1). Decouple the measurement from both the ABI commitment and the learned ranker.
- The decision is framed as more open than it is, but the packet is less guilty of over-selling than a flat 'relabel' verdict suggests. B is ~70-80% shipped, so the architecture pick is largely settled; however DESIGN_B 4.2's falsifiable decision and the 'Phase 0 + A path, not model training' recommendation are honest engineering content, not packaging. Net: agree the choice is substantially made by the tree; disagree that B's distinct value is merely a narrative — its value is the P0 corrections + ABI freeze + the out-of-process broker/proposal-validation discipline for when real models go in-loop.
- A minor real boundary leak the docs assume clean: GoalArbiter.resolve (arbiter.py:141) vetoes a waypoint goal only when all() waypoints are lethal, so a mixed safe/lethal goal passes and relies on grid_v1 to replan. Sound in practice, but name it explicitly for P0 hardening rather than presenting the goal->free-space boundary as already clean.

## What the plan MISSES (against codebase reality)

- CI/eval automation is load-bearing yet unowned and absent from Phase 0. No .github/workflows, no tox/nox/Makefile; 222 test files and rich eval harnesses (evals/companion_nav, nav_instruct, BARN promotion-gate tests) exist but there is NO runner/scheduler. Every promotion gate in SHARED_FOUNDATION 11 and COMPARISON 11 (frozen digest, paired stats, no-regression margins) is therefore manual and aspirational, and A's model-off non-inferiority is currently unfalsifiable so A silently bit-rots. Scope is small: wire a per-commit runner over EXISTING harnesses that enforces model-off + latency-tail + hard-safety regression, not build eval from scratch.
- Cross-session / episodic owner memory is essentially unaddressed and no design owns it. Shipped memory is a flat sqlite ConversationMemory.recent(8) audit log plus a within-run SemanticMemory2D with a 600 s decay half-life (explicitly transient); grep of all six design docs for episodic/cross-session/retrieval returns nothing substantive. For a dog that walks beside the same owner daily this is product-critical and orthogonal to A/B/C — choosing B does nothing for it. It needs a first-class proposal-only memory contract with the same staleness/provenance discipline as sensors.
- The camera is proven but is not yet the mission ingress, and closing that gate is a distinct unscheduled item, not a sub-bullet of 'stronger semantic perception'. runtime.py:4879 still derives candidates via semantic_candidates_from_observation(observation) (sim-fed), and the installed perception_chain consumes detection_adapter, whose adapter.py header says 'GT / clean detections -> DetectionMsg ... Pure RNG + math; no pixels'. The real open-vocab detector (B3) is pending, yet all three designs' grounding algorithms presume fresh camera detections as input.
- route_memory/ (citywalker, vlfm, vpr, teach_repeat, proposer, runtime_hook) is built-but-unwired — grep for it across src outside its own package returns zero hits, and DESIGN_C line 207-208 confirms it is intentionally gate-off. This is exactly the long-horizon/topological memory the companion needs at low net-new cost, yet the phase plan folds it vaguely into B's Phase-3 'advisory map-provider interface' rather than naming 'wire route_memory as a proposal-only source' with the staleness/provenance discipline the tree already models.
- The plan treats P0 as a uniform block but the codebase shows sharply different maturity per item: P0-A/P0-B (exact-zero-after-shaping, fail-closed) are the actual safety-critical, still-open items; P0-C's executive half is done but its proposal-buffer flush is missing; P0-G (approach vs follow) is partially in TaskExecutive; P0-H is latent hygiene. The plan should rank P0 by residual-risk-times-liveness, not present all eight as equal release blockers.

## Recommended action

Adopt the packet's composition as recorded (B target / A mandatory baseline / C learned-ranker deferred) — it is correct and low-risk — but treat it as ratifying an already-B-shaped tree, and rewrite Phase 0 around what the codebase actually needs, not the architecture bake-off. Concretely: (1) Freeze the ABI (SHARED_FOUNDATION section 4) and land the P0 corrections RANKED BY LIVENESS: P0-A exact-zero-after-shaping and P0-B fail-closed-HOLD first (real, safety-critical, still open); P0-C's missing piece next — bind ProposerBus/GoalArbiter buffers to the executive plan_revision/channel_epoch so a correction atomically flushes stale proposals (arbiter.py has no revision key today); then P0-H as dimensional hygiene, folded into unifying the three proximity consumers onto one clearance convention (authority/collision/reactive_safety), and explicitly harden the GoalArbiter mixed-lethal-waypoint case (arbiter.py:141 all()). (2) Make a CI/eval runner over existing harnesses a Phase-0 PEER of the ABI freeze — enforce per-commit model-off non-inferiority + latency-tail + hard-safety regression, or the A-baseline guarantee and every promotion gate are unenforceable. (3) Add two lanes the plan under-owns: close the pixel->detector->grounder camera ingress (blocked on B3), and give cross-session episodic owner/place memory a first-class proposal-only contract; also wire the built-but-unwired route_memory package as a proposal-only source. (4) For C, pull FORWARD only the offline measurement subset (candidate logging + counterfactual-oracle replay in the eval harness) so the residual that gates the ranker is actually measurable, while keeping the learned ranker and the full multi-candidate runtime ABI deferred until that instrumentation proves a selection residual. Do NOT reopen the A/B/C choice; the high-value decisions are the P0 ranking, the CI ownership, and the three missing subsystems.
