# Evaluation frameworks for LLM agents and embodied systems — research report for Parcel

## Key works and systems

**1. τ-bench / τ²-bench (Sierra, 2024–2025)** — [arXiv:2406.12045](https://arxiv.org/abs/2406.12045), [Sierra blog](https://sierra.ai/blog/benchmarking-ai-agents), [τ²-bench](https://arxiv.org/pdf/2506.07982)
Evaluates tool-using conversational agents against a simulated user + domain policy, then verdicts **deterministically by comparing final database state to an annotated goal state** — the conversation is never judged for success, only the world-state is. Headline metric is **pass^k**: fraction of scenarios solved on *all k* independent rollouts (GPT-4o: <50% pass^1 but <25% pass^8 in retail).
*Why it matters for Parcel:* this is the closest published analogue to your proposer/disposer split — the sim world-state (MuJoCo poses, arrival regions, e-stop latch) is your database, and voice_corpus_v1's `expected` column is already a goal-state assertion. *Implication:* keep verdicts anchored in sim ground truth, and add **pass^k for reliability-critical behaviors** — F6 (suspected missed spoken e-stop) is by definition a pass^k failure invisible to single-run scoring. E-stop should be scored fail-closed: any miss in k trials fails the gate.

**2. Agentic Benchmark Checklist / "rigorous agentic benchmarks" (2025)** — [arXiv:2507.02825](https://arxiv.org/pdf/2507.02825)
Audits agent benchmarks for **task validity** and **outcome validity**; finds bugs (τ-bench counted empty responses as success; SWE-bench Verified has insufficient tests) that misestimate capability by **up to 100% relative**. *Implication:* your seeded-defect discipline should extend to the **eval harness itself**: run a null agent (says nothing), an always-claims-success agent, and a random-tool agent through every suite; any suite they pass is broken. This is cheap and would have caught e.g. a verdict script that treats "no transcript" as a pass.

**3. AgentBench + agent-eval surveys (2023–2025)** — [AgentBench, ICLR 2024](https://proceedings.iclr.cc/paper_files/paper/2024/file/e9df36b21ff4ee211a8b71ee8b7e9f57-Paper-Conference.pdf), [Evaluation & Benchmarking of LLM Agents: A Survey](https://arxiv.org/pdf/2507.21504), [survey repo](https://github.com/Asaf-Yehudai/LLM-Agent-Evaluation-Survey)
Multi-environment agent evaluation; the survey literature's consensus gaps are **fragmented metrics, high reproduction cost, and outcome-only scoring that ignores trajectories**. *Implication:* score the trajectory (which tools proposed, which disposed, in what order), not just the end state — Parcel's single-beat tool turns make trajectory assertions tractable and cheap.

**4. HELM (Stanford, 2022)** — [arXiv:2211.09110](https://arxiv.org/abs/2211.09110), [live site](https://crfm.stanford.edu/helm/)
The canonical multi-dimensional eval: a fixed **scenario × metric matrix** (accuracy, calibration, robustness, fairness, toxicity, efficiency measured for *every* scenario, so non-accuracy metrics can't fall off the dashboard). Its top-level aggregation, **mean win rate**, is widely criticized: it's ordinal-only, hides magnitudes, and shifts when the model pool changes. *Implication for the improved eval model:* publish a **fixed dimension × suite matrix** (nav, conversation, safety, honesty, memory, latency, cost — each measured on every applicable scenario), with **per-dimension gates and no single blended scalar**. If you need one comparison number for A/B, use win-rate **against a frozen baseline build**, not against a moving pool — and never let safety average against conversation quality.

**5. LLM-as-judge reliability literature (2023–2026)** — [MT-Bench/Chatbot Arena, arXiv:2306.05685-lineage; survey](https://www.sciencedirect.com/science/article/pii/S2666675825004564), [bias overview](https://www.emergentmind.com/topics/llm-as-a-judge-component)
Established results: **position bias** (up to 75% first-position preference), **verbosity bias**, **self-preference** (10–25%, correlated with self-recognition), and a ~**80% judge-human agreement ceiling** — about the same as human-human. Mitigations: both-orders swap + averaging, rubric anchoring, reference-guided grading, abstention on unparseable output, and **local calibration against human labels**. *Implication:* your AutoRater already implements both-orders and abstention-as-None (both correct per this literature). The missing piece is **meta-evaluation**: a frozen set of ~50–100 rater verdicts hand-labeled by the owner, with judge-owner agreement tracked as its own regression metric. Keeping the judge (Qwen3-32B) a different model family from the policy (GPT Realtime) already neutralizes self-preference — preserve that invariant.

**6. OpenEQA (Meta, CVPR 2024)** — [paper](https://openaccess.thecvf.com/content/CVPR2024/papers/Majumdar_OpenEQA_Embodied_Question_Answering_in_the_Era_of_Foundation_Models_CVPR_2024_paper.pdf)
1,600+ human-written questions about real scenes; scores open-vocabulary answers with **LLM-Match** (judge rates semantic similarity to a reference answer 1–5), validated in blind user studies to **correlate with humans as well as humans do with each other**. GPT-4V scored 48.5% vs human 85.9%. *Why it matters:* this is the ready-made template for the **F3 scene-answerability capability and its eval** — a fixture set of (scene state, question, reference answer, answerable?/unanswerable?) tuples, scored by LLM-Match, with "answerable-but-claimed-blind" (false blindness) and "unanswerable-but-answered" (hallucination) as separate counted failure classes.

**7. BEHAVIOR / BEHAVIOR-1K (Stanford, 2021–2023)** — [BEHAVIOR](https://arxiv.org/pdf/2108.03332), [BEHAVIOR-1K](https://proceedings.mlr.press/v205/li23a/li23a.pdf)
Defines tasks as **first-order-logic goal predicates** (BDDL); primary metric is the **fraction of satisfied goal literals** (partial credit), with efficiency (SPL, collisions, energy) strictly **secondary and never blended into success**. *Implication:* formalize Parcel's arrival semantics and task goals as predicates over MuJoCo state (you already have INSIDE/NEAR region semantics in queries.tsv — this is BDDL-lite); adopt the primary/secondary split so latency and cost never contaminate the success verdict.

**8. Gemini Robotics 1.5 evaluation practice (Google DeepMind, 2025)** — [tech report](https://arxiv.org/pdf/2510.03342)
Production VLA eval at scale: **>90% of eval episodes run in MuJoCo simulation**, with sim scenes visually/physically aligned to real cells and validated by **rank consistency** (sim ordering of model variants must match real ordering); real-robot comparisons run as **A/B/n interleaved on the same cell** to kill environment drift. *Implication:* Parcel is natively MuJoCo, so the expensive resource is the **owner's live spoken time**, not hardware. Treat live owner sessions as the "real robot": periodically run the same scenario set recorded-vs-live and check that variant rankings agree; when comparing two stack builds live, interleave them within one session rather than sequential sessions.

**9. π0 (Physical Intelligence, 2024) + RoboArena (2025)** — [π0 blog](https://www.pi.website/blog/pi0), [RoboArena](https://arxiv.org/abs/2506.18123)
π0 scores each episode with a **task rubric giving partial credit** (normalized 0–1) over many trials, on tasks deliberately harder than academic benchmarks. RoboArena crowd-sources **double-blind pairwise comparisons** of policies across freely-chosen tasks; its task-aware aggregation **outperformed both Elo and Bradley-Terry**, and 600+ episodes ranked policies more accurately than centralized eval. *Implication:* for whole-stack changes where deterministic assertions can't decide (persona, helpfulness), pairwise-blind comparison against the incumbent build is the most sample-efficient scheme — which your ComparativeAutoRater already is. RoboArena's lesson is to be suspicious of Elo-style global scalars; keep comparisons anchored to a frozen incumbent.

**10. CheckList (Ribeiro et al., ACL 2020)** — [paper](https://aclanthology.org/2020.acl-main.442/), [repo](https://github.com/marcotcr/checklist)
Behavioral testing matrix: **MFTs** (unit-test examples), **INV** (label-preserving perturbations must not change output), **DIR** (directed perturbations must change it a known way). Practitioners with CheckList found ~3x more bugs. *Implication:* voice_corpus_v1 is currently all-MFT. Add INV rows (same query + TV-audio overlay, + reverb, + paraphrase → same tool call) and DIR rows (negation: "don't go to the bench" → no navigate_to; "stop" injected mid-utterance → e-stop). These generate cheaply from your existing 52 recordings by audio mixing — offline, without touching the live reSpeaker stream on :8765.

**11. Device-directed speech detection + VoiceBench (Apple/Amazon 2022–2024; TACL 2026)** — [Apple DDSD](https://machinelearning.apple.com/research/device-directed-speech), [multimodal DDSD w/ LLMs](https://arxiv.org/html/2403.14438), [follow-up-mode DDSD](https://arxiv.org/html/2411.00023v2), [accidental smart-speaker triggers](https://arxiv.org/pdf/2008.00508), [VoiceBench](https://arxiv.org/abs/2410.17196)
The industry framing for exactly F1: "should this utterance command the device" is an utterance-level classifier evaluated as a **FAR/FRR trade-off curve (EER)** — never single accuracy — and the literature's **top false-trigger class is television dialogue** with interrogative prosody. VoiceBench adds the robustness axes (speaker characteristics, environment, content complexity) for LLM voice assistants. *Implication:* the F1 speech-identity capability needs a two-sided corpus: positive (owner utterances — you have 52) and **negative (TV audio, other speakers, owner speech not addressed to the robot)**, scored as FAR at a fixed FRR budget. The XVF3800's beamforming direction-of-arrival is a free auxiliary signal for device-directedness that pure-cloud stacks don't have.

**12. Safety cases (UL 4600 / GSN, 2020–) + production eval-tiering practice (Husain & Shankar et al., 2024–2025)** — [UL 4600 overview](https://edgecaseresearch.medium.com/an-overview-of-draft-ul-4600-standard-for-safety-for-the-evaluation-of-autonomous-products-a50083762591), [Open Autonomy Safety Case Framework](https://arxiv.org/pdf/2404.05444), [GSN for AV safety cases](https://sres.ai/autonomous-systems/from-evidence-to-argument-using-gsn-to-structure-av-safety-cases/), [Evals FAQ](https://hamel.dev/blog/posts/evals-faq/), [Pragmatic Engineer guide](https://newsletter.pragmaticengineer.com/p/evals), [Vercel primer](https://vercel.com/i/what-are-llm-evals-developers-primer)
UL 4600 structures assurance as **claims → argument → evidence**; GSN makes the mapping explicit and, crucially, makes **uncovered claims visible**. Production LLM practice converges on three tiers: **per-change CI gate (small, deterministic-first, <10 min), scheduled deep suites (judged, pass^k, overnight), and live monitoring whose error analysis feeds new fixtures back into the gate**; deterministic checks are preferred over judges wherever possible. *Implication:* this is the "one legible verdict" answer — see Design pressure below.

## Design pressure on Parcel's existing eval assets

### What the assets already get right
- **Deterministic-first with frozen baselines.** The 6600-test commit gate with frozen nav-safety baselines and seeded-defect discipline is exactly the regression/capability separation production practice recommends, and it predates the ABC paper's argument that eval harnesses need their own defect testing.
- **AutoRater bias hygiene.** Both-orders comparison, abstention-as-None (not laundered to a tie), judge model family (Qwen) distinct from policy family (GPT Realtime), and the dual `punts_rule`/`punts_llm` track with the gap treated as drift signal — all directly aligned with the judge-reliability literature. This is better hygiene than most published autoraters.
- **Goal-state assertions in the voice corpus.** `expected = navigate_to bench; arrival NEAR` is τ-bench-style end-state verdicts and BDDL-lite predicates — the right substrate.
- **Failure-taxonomy-driven fixture growth.** F1–F6 out of a live owner session feeding new corpora is precisely the production monitoring→CI loop.

### What is wrong or missing
1. **No reliability dimension (pass^k).** Everything is scored on one rollout. F6 is a reliability failure by construction. Add pass^k on a small safety-critical set (spoken e-stop, keepout, yield) with **min/veto aggregation** — one miss fails; and report e-stop response latency as a worst-case, not a mean.
2. **No rejection corpus — F1 is structurally invisible.** All 52 queries are owner-directed positives; a system that accepts *every* voice scores 100%. The corpus needs a negative half (TV audio, non-owner speakers, owner speech to another person), scored as FAR/FRR — the DDSD literature says single-accuracy scoring of this task is meaningless. Buildable offline by mixing TV/recorded audio into existing WAVs; no need to touch the live mic stream.
3. **The judge is uncalibrated.** No local human-agreement measurement exists for the Qwen3-32B judge. Literature's ~80% agreement figures are from other domains and cannot be assumed. Create a frozen owner-labeled verdict set; track judge-owner agreement as its own gated metric; re-run it whenever the judge model or prompts change.
4. **Honesty is judged where it could be asserted.** F2 (completion over-claim) and half of F3 (false blindness) are deterministically checkable in Parcel because **MuJoCo state is fully observable** — cross-reference every completion/ability claim in the transcript against sim ground truth (claimed arrival vs arrival semantics; claimed "can't see" vs object actually in view frustum). This is Parcel's structural advantage over real-robot labs; reserve `honesty_groundedness` (the judge) for phrasing-level over-claims only.
5. **No cross-session memory fixtures (F4).** LoCoMo ([overview](https://www.emergentmind.com/topics/locomo)) shows the shape: multi-session fixtures with single-hop/multi-hop/temporal probes, scored by reference-answer LLM-match. The 25-thread SI-v1 corpus with prompt provenance is seed material; what's missing is probes that span sessions.
6. **No idle/null-input soak (F5).** An INV-style invariance suite: N minutes of ambient audio (TV, silence, hallway noise) must produce zero state transitions, zero tool proposals. Trivial to run headless; would have caught idle-lane rollover automatically.
7. **No aggregation design at all.** Nothing currently combines nav + conversation + safety + honesty + memory + latency + cost. Recommended synthesis from the literature: a **fixed dimension × suite matrix (HELM), per-dimension typed verdicts** — safety/reliability as hard veto gates (pass^k, worst-case), honesty as deterministic assertion counts, conversation quality as pairwise win-rate vs frozen incumbent (RoboArena/AutoRater), latency/cost as budget thresholds (BEHAVIOR's secondary-metric discipline) — rolled up not into a scalar but into a **GSN-style claims table**: top-level claims ("only the owner's voice commands Parcel", "Parcel never claims what it didn't do", "spoken e-stop always halts within X ms"), each pointing at named evidence artifacts under `evals/`. The one legible verdict is "all claims currently evidenced: yes/no, and which claim broke." Every F1–F6 failure was an *unstated claim with no evidence obligation* — the claims table makes that class of gap visible before the live session does.
8. **Eval-harness validity untested.** Run ABC-style null/trivial/always-claim-success agents through every suite as part of the gate. Given τ-bench itself shipped an empty-response-counts-as-success bug, assume yours has one until proven otherwise.

### Pitfalls to avoid
- **A single blended score.** The HELM mean-win-rate criticism applies with force: a conversation-quality win can hide a safety regression. Ordinal aggregates also silently reshuffle when the comparison pool changes.
- **Averaging safety.** Safety and reliability dimensions aggregate by min/worst-case, everything else can average.
- **Goodharting `punts_rule`** (model learns the rule's phrasings) — the README's gap-monitoring instinct is the correct defense; keep it.
- **pass^k cost blowup.** Reserve high k for the small safety set; k=1 for the broad corpus; tier suites per production practice (deterministic per-change gate <10 min; judged + pass^k nightly; live owner session weekly).
- **Judge drift on silent judge upgrades** — pin the judge build in the verdict metadata and re-calibrate on change, same discipline as the frozen nav baselines.
- **Overfitting to the 52 queries.** Rotate a held-out slice; grow variants via CheckList-style perturbation rather than hand-authoring.
- **Sim-live divergence.** Adopt Gemini Robotics' rank-consistency check between recorded/replayed runs and live sessions before trusting recorded-run verdicts for decisions.

### What would have caught F1–F6 automatically
| Failure | Automatic catch | Source pattern |
|---|---|---|
| F1 TV hijack | Negative/rejection corpus scored as FAR at fixed FRR | DDSD / false-trigger-mitigation literature |
| F2 completion over-claim | Deterministic claim-vs-sim-state assertion | τ-bench end-state verdicts |
| F3 false blindness | Answerable/unanswerable scene-QA fixtures, LLM-Match scored, false-blindness counted separately | OpenEQA |
| F4 memory amnesia | Cross-session probe fixtures | LoCoMo |
| F5 idle-lane rollover | Ambient-audio invariance soak (zero transitions expected) | CheckList INV |
| F6 missed spoken e-stop | pass^k with veto aggregation + worst-case latency | τ-bench pass^k, safety-case gating |
