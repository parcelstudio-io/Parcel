# Dual-system architectures where a slow language model steers a fast controller and the robot talks while acting

Literature note for the Parcel "Model A / Model B" study. Written 2026-08-29. Every source below was fetched and read on that date (arXiv HTML/abs, project pages, model cards, GitHub READMEs); numbers are quoted from the fetched text, not from memory. Where an extraction was ambiguous it is flagged.

Scope: the closest precedents for "a slow language-level model (Model B) steering a fast trainable controller (Model A) while the robot keeps talking to the user". For each system: how user interjections are injected, what the high level outputs, the rate of each level, how progress/completion is reported back in language, data + compute, success numbers, availability.

## 1. Hi Robot (Physical Intelligence, Feb 2025; ICML 2025)

- arXiv abs: https://arxiv.org/abs/2502.19417 ; full text: https://arxiv.org/html/2502.19417 ; project page: https://www.pi.website/research/hirobot
- Authors: Shi, Ichter, Equi, Ke, Pertsch, Vuong, Tanner, Walling, Wang, Fusai, Li-Bell, Driess, Groom, Levine, Finn.

**Structure.** High-level policy p^hi(l_hat_t | I_t, l_t): a PaliGemma-3B VLM takes images + the open-ended prompt and "produces an intermediate language command" (atomic skill label like "pick up the lettuce"). Low-level: "the pi0 VLA, which is trained by finetuning PaliGemma-3B with an additional flow matching 'action expert' to produce continuous actions" (pi0 = 3B + 300M = 3.3B; see pi0 below). p^lo(A_t | I_t, l_hat_t, q_t).

**Rates.** "we rerun high-level inference and recompute l_hat_t either when one second has elapsed, or when a new interaction with the user takes place." Low-level: "73 ms on-board" per step (Appendix B.3), 50 Hz with action chunking.

**Interjections.** A new user utterance triggers HL re-inference (event-driven prompt refresh). The HL sees the image, so "it can correctly ground feedback like 'that's not trash'". After an interjection ("leave it alone") is fulfilled, "the user can signal to the robot that it may switch back to the previous command and continue the task execution."

**Talk-back.** "the high-level policy has the option to include a verbal utterance u_t in the command l_hat_t, which can be confirmations or clarifications from the robot. When u_t is included, we use a text to speech system to play the utterance." Speech I/O: lavalier mic, Whisper large-v2 STT, a hosted TTS API.

**Data.** Teleop demos segmented into 1-3 s skills with labels; synthetic prompts/interjections: "We prompt p^gen with both the visual context and the skill label ... p^gen then imagines an appropriate interaction that might have led to l_hat_t", with scenario types "negative task, situated correction, specific constraint". Conditioned on prior skill labels in the episode.

**Compute.** "Training the high-level policy is highly efficient, requiring approximately 2 hours on 8xH100 GPUs." AdamW, lr 1e-5, batch 512. Inference on "one to two NVIDIA GeForce RTX 4090".

**Results (project page numbers).** Instruction accuracy / task progress:
- Table bussing: Hi Robot 74 / 77; flat VLA 36 / 61; GPT-4o HL 35 / 63.
- Sandwich: 83 / 80; 34 / 42; 13 / 56.
- Grocery: 72 / 85; 39 / 28; 41 / 72.
- Average: **Hi Robot 76 / 81; flat VLA 36 / 44; GPT-4o 30 / 64.** "Hi Robot averages over 40% higher instruction accuracy than GPT-4o".
- Without synthetic data "the ablated model ignores clarifications". Expert-human HL baseline near flawless -> "failures stem more from reasoning than actuation".

**Robots.** UR5e, bimanual ARX, mobile ARX (16-D action).

**Limitations (verbatim themes).** "Difficulty with instructions requiring long-context reasoning, since the current system lacks memory"; LL "temporarily ignoring instructions"; "the training process decouples the high-level and low-level models, and they are not aware of one another's capabilities except through the training examples."

## 2. pi0 and pi0.5 (Physical Intelligence, 2024/2025)

- pi0: https://arxiv.org/html/2410.24164 — "PaliGemma ... 3 billion parameter VLM"; "We add 300M parameters for the action expert ... for a total of 3.3 billion parameters"; H=50 chunk; "up to 50 Hz"; "pre-trained on over 10,000 hours of robot data" across "7 different robot configurations and 68 different tasks"; "73 ms" on-board inference on RTX 4090; uses "a high-level VLM" to decompose "bus the table" into "pick up the napkin".
- pi0.5: https://arxiv.org/html/2504.16054 ; blog https://www.pi.website/blog/pi05

**Hierarchical inference inside one network.** "the model first predicts the semantic subtask, inferring the behavior that is appropriate to perform next ... and then predicts the low-level robot action chunk based on this subtask." HL "still runs at a lower frequency than low-level action inference". 50 Hz target-pose commands, 10 denoising steps.

**Data.** "About 400 hours of data of mobile manipulators performing household tasks in about 100 different home environments"; "97.6% during the first training phase do not come from mobile manipulators performing household tasks"; sources: ME (static arms in homes), CE (lab cross-embodiment + OXE), HL (subtask labels), WD (CapsFusion, COCO, Cambrian-7M, PixMo, VQAv2), **VI (verbal instructions): "expert users providing 'language demonstrations,' selecting appropriate sub-task commands"** — i.e., a human coaching the robot step by step is a training signal.

**Results.** Evaluated in 3 real unseen homes; "after only about 100 training environments, it actually approaches the performance of the baseline" trained on the test homes; "no VI" causes "significant degradation in performance"; removing web data hurts OOD objects; the implicit-HL ablation (no subtask prediction) is "the second best model". Blog quotes language-following rates (in-dist follow 86% / success 83%; OOD follow 94% / success 94%) — treat as extracted from a figure, not verified in text.

**Availability.** No weight release stated in either document.

## 3. Figure Helix (Feb 2025)

- https://www.figure.ai/news/helix
- S2: "a 7B-parameter open-source, open-weight VLM pretrained on internet-scale data", "7-9 Hz". S1: "an 80M parameter cross-attention encoder-decoder transformer", "200 Hz".
- Interface: S2 produces "a single continuous latent vector, passed to S1 to condition its low-level actions"; S1 always uses "the most recent S2 latent vector".
- Data: "~500 hours in total" of teleop, "<5%" of prior VLA datasets; hindsight instructions from an auto-labelling VLM ("What instruction would you have given the robot to get the action seen in this video?").
- Deployment: "each running on dedicated GPUs" on "dual low-power-consumption embedded GPUs".
- No speech, no success percentages ("thousands of novel items in clutter").
- Lesson: the S2->S1 interface is a latent, so nothing in the fast loop is narratable; talk-back would have to come from a separate S2 head.

## 4. NVIDIA GR00T N1 (Mar 2025)

- https://arxiv.org/html/2503.14734
- System 2: "NVIDIA Eagle-2 VLM", "1.34B in the VLM" (2.2B total), "runs at 10Hz on an NVIDIA L40 GPU", 224x224 images -> 64 tokens/frame.
- System 1: flow-matching DiT, "4 inference steps", "120Hz", chunk "H=16", "63.9ms on an L40 GPU using bf16"; coupled by cross-attention to VLM output tokens.
- Data pyramid: 88 h humanoid teleop; 827 h neural (video-model) trajectories; 780,000 sim trajectories = 6,500 h; human video (Ego4D, EPIC-KITCHENS ...).
- Compute: "roughly 50,000 H100 GPU hours" pretrain; up to 1024 GPUs; neural trajectory generation ~105k L40 GPU-h.
- Results: RoboCasa 32.1% vs DP 25.6%; DexMimicGen 66.5% vs 56.1%; GR-1 tabletop 50.0% vs 32.7%; real-robot avg 76.8% vs 46.4%; 10%-data 42.6% vs 10.2%.
- Availability: "CC BY 4.0"; checkpoint, data, sim benchmarks public (github.com/NVIDIA/Isaac-GR00T).
- No speech. Interface again is VLM tokens, not language.

## 5. ELLSA — End-to-end Listen, Look, Speak and Act (ByteDance SALMONN / Tsinghua, Oct 2025)

- https://arxiv.org/abs/2510.16756 ; full text https://arxiv.org/html/2510.16756 ; weights https://huggingface.co/tsinghua-ee/ELLSA
- Claim: "the first full-duplex, end-to-end model that simultaneously perceives and generates across vision, text, speech, and action within a single architecture".

**Architecture.** SA-MoE: Speech Expert = LLaMA-3.1-8B-Instruct (32 layers, 4096 hidden); Action Expert = Emu3-Base (same shape); streaming Mamba speech encoder (32 blocks, 2048). "At any moment, only one expert's weights are activated." HF card: **18B params, Apache 2.0**, base models Emu3-vision, Llama-3.1-8B-Instruct, CosyVoice2-0.5B, UniVLA-LIBERO.

**Time blocks.** "Within each time block, inputs and outputs from different modalities are organized in a fixed sequence: speech input, image input, text output, and action output." Block = 1 s; speech at "5 Hz" (from a 25 Hz encoder), 1 image/s, "8 tokens of text output (or a single <silence> token)", then "one second of speech and action output".

**Duplex behaviours and numbers (LIBERO).**
- Action barge-in ("Stop now", "Pause here"): **94.3%**.
- Dialogue turn-taking 100.0%; action turn-taking 100.0%; defective-instruction rejection 100.0% (visual/semantic/motion/out-of-context).
- Speaking-while-acting: a spoken query arrives "2-8 seconds after the initial action instruction"; **73.2% on LIBERO-LONG with concurrent generation vs 84.4% acting alone** (an 11.2-point cost of talking).
- Context-grounded VQA during execution (12 progress questions over 9 LIBERO-LONG tasks): ~80%.
- Manipulation avg **89.4% vs pi0-FAST 85.5%, CoT-VLA 81.1%**.
- Speech: Llama Questions S2T/S2S 74.7/70.0 (Freeze-Omni 74.2/56.2); Web Q 39.5/36.5; TriviaQA 45.2/41.7.
- Latency: "Per-time-block latency ... 854ms" speech-to-speech, "786ms" speech-to-action, on A100.

**Data.** LibriSpeech 281k + GigaSpeech 200k (ASR); 729k QA samples; LIBERO 3,386 samples; 1,693 rejection samples. Three stages (40k steps; 500 steps bs 1024; 20k steps bs 256).

**Limitations.** "handles only a limited range of scenarios ... backchanneling, remain unaddressed"; "ELLSA has yet to be validated in real-world settings."

## 6. VITA-E (Oct 2025)

- https://arxiv.org/abs/2510.21817 ; full text https://arxiv.org/html/2510.21817
- "a dual-model architecture where two parallel VLA instances operate as an 'Active Model' and a 'Standby Model'"; VLM part is VITA-1.5 (frozen), action expert is "the Diffusion Transformer from GR00T".
- Model-as-controller: the VLM emits "[RES]" (voice-only), "[ACT]" (response includes a physical action), "[HALT]" (immediate stop), "[END]" (multi-step sequence complete), "[INST]" ("Delimits the spoken part of an action response from the internal action instruction"). Output "S_t=(c_t, L_t^robot, C_t^robot)".
- Interrupt routing: "While the Active Model (I) is generating a verbal response ... any subsequent input will be routed to the Standby Model (II) ... it signals a preemption event that instantly terminates the Active Model's speech generation."
- Numbers (30 trials): speech interruption 100%, emergency stop 100%, task switching 93.3%; voice response latency 2.26 s avg (10 tests). LIBERO below the GR00T baseline.
- Data: "300 demonstrations by teleoperating the robot arm at 20 Hz" per task; synthetic interruption data by injecting "Stop!" at random points; bs 64, lr 1e-4, 20k steps.
- Fourier GR2 humanoid, RealSense D455 head camera. Homepage https://lxysl.github.io/VITA-E/ ; no code release stated.

## 7. DuplexSLA (StepFun / NTU, May 2026)

- https://arxiv.org/abs/2605.20755 ; full text https://arxiv.org/html/2605.20755v1 ; repo https://github.com/hyzhang24/DuplexSLA
- Abstract: "a native full-duplex Speech-Language-Action foundation model that decodes assistant audio together with a structured action stream on a shared 160 ms chunk timeline."
- Channels per 160 ms chunk: user channel "2 causal features at an 80 ms stride"; assistant channel "TA4 layout ... one text anchor token T followed by 4 audio tokens A at a 40 ms stride"; action channel = "delayed transcript text, planning text, interaction-control labels, or structured tool calls", **"at 10 text tokens per chunk ... tokens that do not fit spill into the action segments of the following chunks."**
- "Planning text and JSON-style tool calls are emitted on the action channel while the assistant TA4 channel keeps producing speech".
- Turn-taking decided "based on the model's internal semantic state, rather than on a separate VAD module": interrupt -> "emits an interrupt label on the action channel and switches the assistant TA4 to silence"; backchannel -> label, assistant continues; pause -> stay silent.
- Backbone: README says "Step-Audio-2-mini (~7B parameters)" (the HTML extractor read "77B-scale", which conflicts with the README; treat ~7B as correct). CPT ~500k h audio (duplex dialogue ~320k h, ASR 2x90k h) + 1.92M text; post-training ~50k h (interrupt/backchannel/pause ~36k h, tool-call ~14k h).
- DuplexSLA-Bench: 2,100 cases (1,200 turn-taking, 900 tool-call). With prefill: normal 96.00% @ 0.27 s; pause 93.33% @ 0.27 s; **interrupt 99.33% @ 0.40 s; backchannel 98.33% @ 0.32 s**. Without prefill: 94.34% avg @ 0.30 s vs GPT-4 Realtime 96.50% @ 1.57 s. Tool call: 85.56% @ 0.64 s vs ASR+LLM cascade 91.33% @ 2.77 s ("~4x lower tool-call delay").
- "Action" here is tool calling over a 50-function cabin/smart-home schema (includes "navigate") — **no robot**.
- Hardware note: "Per-chunk decoding cost ... leaves room for only a small number of action-channel tokens per chunk." "open-source duplex backbones without targeted post-training collapse on the pause subset".
- License MIT (repo) / CC BY 4.0 (paper); "Inference code, deployment recipes, and model checkpoints are not yet released."

## 8. RoboEgo / FLM-Ego system card (BAAI / NTU, Jun 2025)

- https://arxiv.org/abs/2506.01934 ; full text https://arxiv.org/html/2506.01934
- "Our backbone model is a 7-billion-parameter autoregressive LLM"; per time step it attends to context/time-aligned visual embeddings, both audio channels (speak, listen) and all prior text tokens.
- "achieving a theoretical duplex latency of 80 ms"; text-first strategy: "we place its corresponding semantic token at t, and initiate the full textual monologue at t - spk_delay".
- "lightweight decoders for audio, language, and action modalities generate their respective tokens based on a shared hidden state produced by the backbone model".
- LEJU Kuavo humanoid: locomotion from speech + camera, telepathy game with gestures. Locomotion 96.5%, telepathy 97.2%. Chat vs Qwen2.5-Omni: helpfulness 7.2 vs 7.4, naturalness 8.2 vs 7.9, responsiveness 8.8 vs 8.1, robustness 8.0 vs 7.7 (5 annotators).
- Data sizes and inference hardware not disclosed; no release stated. Limitation: streaming visual encoders "still fall short" so time-division multiplexing is used for visually intensive tasks.

## 9. RT-H (Google DeepMind, 2024)

- https://arxiv.org/html/2403.01823
- Two queries in one PaLI-X 55B model: language motion ("move arm forward", "close gripper"; >2,500 motions) then action given the motion.
- Correction: "users can directly intervene on the learned language motions"; "type a new language motion correction on the keyboard or use hotkeys"; only the language-motion query is updated ("we do not need to re-train the action query").
- Timing: "asynchronous querying: we train just the language motion query in RT-H to predict the skill one step into the future"; during intervention, re-query "at a fixed frequency" so the user can update or release.
- Data: 100K demos (70K kitchen + 30K diverse). Results: "+15% on average" over RT-2 (6/8 tasks); "RT-H-Intervene brings the average success rates of RT-H from 40% to 63% with just 30 episodes of correction per task"; novel objects 65% vs 55%.

## 10. OLAF (2023)

- https://arxiv.org/html/2310.17555 — "Interactive Robot Learning from Verbal Correction".
- User stops the robot, gives a verbal correction; GPT-4 relabels the "pre-intervention region" (~1-2 s before the stop); policy = ResNet-18 transformer BC, ~19M params.
- Data: sim 50 demos + 100 correction trajectories; real 40 + 80. Results: "+20.0% improvement in policy success rate" avg; "17.8%" from verbal correction alone.

## 11. Yell At Your Robot (Stanford, 2024)

- https://arxiv.org/html/2403.12910
- HL pi_H(l_t | o_{t-k:t}) (ViT with CLIP init) "queried at fixed intervals, specifically every 4 seconds as the average skill length"; LL = ACT with EfficientNet-b3, DistilBERT language encoder; Whisper STT.
- Override: "The user's verbal interventions temporarily override the high-level policy's output, directly influencing the low-level policy." pi_deploy = pi_L(a|o, l_user) if intervention else pi_L(a|o, l_H). User says "stop" to intervene; 2 s of pre-intervention context saved.

- Results (20 trials): oracle corrections +25-50 pts (bag), +30-45 (trail mix), +15-25 (plate); after finetuning HL on corrections +20-45, +15-20, +15-25.

## 21. Cross-cutting patterns

**A. Five ways an interjection gets into the controller (observed).**
1. *Event-driven prompt refresh* — Hi Robot (re-run HL on any user interaction or every 1 s); pi0.5 (subtask re-predicted each HL tick); Inner Monologue (append to prompt after each skill).
2. *Direct override of the language interface* — YAY (user text replaces HL output to the LL; "stop" to enter); RT-H (correction mode replaces the language motion); ECoT (edit the reasoning chain, hold 5 steps).
3. *Native token stream on a chunk clock* — Moshi (80 ms), RoboEgo (80 ms), DuplexSLA (160 ms, 10 action tokens/chunk), ELLSA (1 s blocks). The model decides interrupt/pause/backchannel itself; barge-in 94-99%.
4. *Control tokens emitted by the VLM* — VITA-E ([HALT]/[ACT]/[END]/[INST]) plus a standby instance to preempt the active one.
5. *Replan from history* — ITP (completed steps + chat history + new request); Vocal Sandbox (exception -> teach); ZIPON (feedback dictionary).
Plus, for fast controllers with no language interface: *parameter/goal reconfiguration* — Hey Robot (MPC cost), DualVLN (pixel goal + latent every 500 ms), TIC-VLA (KV features + waypoints every 2 s), Helix (latent every ~120 ms).

**B. What the slow level outputs.** Language subtask (Hi Robot, pi0.5, YAY, RT-H, GR 1.5, ITP) vs latent/tokens (Helix, GR00T, DualVLN, TIC-VLA) vs code/params (CaP, Hey Robot). Only the language-output family is narratable without an extra decoder.

**C. How progress/completion is reported.** Optional utterance in the HL command + TTS (Hi Robot); concurrent speech stream (ELLSA, RoboEgo, DuplexSLA); spoken part delimited from the action instruction, plus an explicit [END] completion token (VITA-E); success detection in language re-fed to the planner (Inner Monologue; GR-ER 1.5 at 5 Hz); thinking traces (GR 1.5, ECoT); structured verbalisation from plan + log (Verbalization 2016, Woofs-to-Words); memory tree for "what did you do" questions (H-EMV).

**D. Costs that show up.** Talking while acting costs 11 points of manipulation success in ELLSA (84.4 -> 73.2); reasoning text costs 50x tokens per step in ECoT (350 vs 7); GPT-4-class HL latency is 1-7 s (ITP, Vocal Sandbox, Hey Robot) versus sub-second only for in-model duplex (Moshi 200 ms, DuplexSLA 0.27-0.40 s, RoboEgo 80 ms theoretical) and Hi Robot's 1 s tick.

**E. Rates seen in the field.** Slow level: 0.5 Hz (TIC-VLA), 1 Hz (Hi Robot), 2 Hz (DualVLN), 5 Hz (GR-ER success detection), 7-9 Hz (Helix), 10 Hz (GR00T). Fast level: 10 Hz (TIC-VLA), 30 Hz (DualVLN), 50 Hz (pi0, pi0.5, QUART-Online, Gemini Robotics), 120 Hz (GR00T), 200 Hz (Helix).

## 22. What this means for Parcel's Model A / Model B

Parcel's ask: Model A = trainable, fully duplex controller that ingests all sensor/voice/context/history streams at a fixed clock and emits local motion (or global-plan updates) plus a *representation* the hosted voice narrates from; Model B = converts an owner voice command into a steerable injection (revise / keep / queue the global plan) and translates Model A's output stream into narration context; global plans as a historical queue.

1. **Nobody has trained the exact stack, but the pieces exist and the interfaces converge on language.** Hi Robot is the closest precedent for Model B -> Model A: a VLM that re-plans every 1 s *or on any user utterance*, emits a short language subtask, and optionally a spoken utterance for TTS. pi0.5 shows the same subtask head can live inside the controller network. GR 1.5 shows the orchestrator/VLA split with success detection at 5 Hz. For Parcel, the "representation the hosted voice narrates from" should be a **language-level subtask + status string on a slow clock**, not a latent: Helix/GR00T/DualVLN latents are not narratable, and every system that talks (Hi Robot, ELLSA, VITA-E, DuplexSLA, GR 1.5) does it from text.

2. **Injection mechanism: adopt the override-switch + history-replan combination, not a token-stream merge.** YAY's rule (user text replaces the HL output to the LL, "stop" to enter) and ITP's replan rule (completed steps + guidelines + new request + chat history) are cheap, deterministic, and map onto Parcel's existing task executive (submit/suspend/resume, transactional amendment) and the owner's "revise / keep / queue" semantics. Hi Robot's "signal to switch back to the previous command" is the "keep/queue" case. Native duplex token merging (ELLSA/DuplexSLA/RoboEgo) buys 0.3-0.4 s barge-in but requires a single 7-18B model with 500k-hour audio corpora (DuplexSLA) — not trainable in Parcel's sim budget.

3. **Keep narration off the control path.** ELLSA's 84.4 -> 73.2 drop when the same network speaks while acting is the only measured cost of tight speech-action coupling, and it is large. Parcel's existing split (hosted Realtime voice + local controller) is the right shape; the coupling should be through the representation stream and the StateDigest, and Model B is the translator both ways (VITA-E's [INST] split between "spoken part" and "internal action instruction" is a concrete output format; VITA-E's [END] token is the "Done!" trigger).

4. **Clock rates are already known.** Slow level 1-2 Hz with event-driven refresh (Hi Robot 1 s, DualVLN 2 Hz), fast level 10-50 Hz. Parcel's 10 Hz duplex frame clock matches TIC-VLA's action policy rate on a Go2; TIC-VLA is the only published Go2-on-Orin dual system (0.75 SR on Orin NX at 0.5 Hz VLM / 10 Hz policy, with RL fine-tuning for latency robustness). DualVLN on Go2 needs a remote 4090 with 20 GB, so a 7B slow level is out of the AGX Orin budget if the hosted voice and SigLIP-2 also run there; a 0.5B-class VLM (TIC-VLA) or a 3B PaliGemma HL (Hi Robot) is the realistic on-device slow level.

5. **Trainable Model B recipe = Hi Robot's synthetic-interjection generation + YAY's correction finetuning.** Hi Robot trained its HL in ~2 h on 8xH100 from teleop skill labels plus VLM-imagined interjections of three types (negative task, situated correction, specific constraint), and ablating the synthetic data made the model "ignore clarifications". YAY got +15-45 points from correction data equal to 4-11% of the base set. Parcel's sim traces (headless city + MuJoCo city) already have nav state / goal / blocked / following / battery in the StateDigest; generate mid-task amendments against those traces the way Hi Robot does, and evaluate with Hi Robot's instruction-accuracy + task-progress metrics.

6. **Narration content has a user-validated shape.** Rosenthal/Veloso: users prefer intermediate abstraction and locality; Woofs-to-Words on a Go2 with blind users: scene + plan verbalisation ("We are approaching an office door", "will take about three minutes") scored 4.83/5 utility. That is exactly the "Sure, I'll check the sofa ... Done! Should I go back to the door?" register. H-EMV's summary tree is the "global history" structure for the historical plan queue and for answering "what did you do while I was gone".

7. **Benchmark blueprint.** Combine: ELLSA's six duplex behaviours (dialogue turn-taking, action turn-taking, defective-instruction rejection, action barge-in, speaking-while-acting, context-grounded progress VQA), DuplexSLA-Bench's pause/interrupt/backchannel accuracy + delay, ZIPON's SIT (success weighted by interaction turns), and Hi Robot's IA/TP. Targets from the literature: barge-in >= 94% (ELLSA) / halt 100% (VITA-E); interrupt decision 0.4 s (DuplexSLA); progress-question accuracy ~80% (ELLSA); instruction accuracy 76% (Hi Robot).

8. **Known failure modes to design around.** Hi Robot: no memory -> long-context instructions fail (Parcel's last-minute + global-history streams address this directly); LL "temporarily ignoring instructions" because of proximity bias; HL and LL "not aware of one another's capabilities" (Parcel's StateDigest capability grounding is the mitigation); ELLSA: no backchannel, not validated in the real world; Gemini Robotics 1.5 does not address user interruption at all.

## 23. Open questions the literature does not settle

- Whether a language representation can be emitted on Parcel's 10 Hz frame clock on an AGX Orin: DuplexSLA notes per-chunk decoding "leaves room for only a small number of action-channel tokens per chunk", and ELLSA needs 786-854 ms per 1 s block on an A100. A 1 Hz slow tick with a 10 Hz fast loop is what the evidence supports.
- No paper compares a latent interface (Helix) against a language interface (Hi Robot) on the same task for either control quality or narratability.
- No published system trains the interjection channel end-to-end for *navigation with mid-task amendments plus speech*; ELLSA and VITA-E are tabletop manipulation, DualVLN and TIC-VLA take one instruction per episode.
- Sim-to-real for speech-conditioned behaviours is unmeasured (ELLSA is sim-only); the Go2-on-Orin numbers (TIC-VLA 0.75) are for single-instruction navigation without speech.
- pi0.5's headline language-following percentages on the blog (86/83, 94/94) are figure-read values; verify before citing.
